# Подключённый локальный AI · 13 октября 2026

Оболочка подключена к существующему FastAPI на том же origin:
`http://127.0.0.1:8000/static/mts-shell/index.html`.
Обычный запуск проекта — `start-local.ps1`, модель в `.env`: `qwen2.5:3b`.
Новый frontend не требует ключей Groq или платной озвучки.

## Что теперь работает

Откройте «Попробовать помощника» или «Тестировать» у своего агента.
Дождитесь подключения и приветствия. Для голосового разговора нажмите микрофон
и разрешите доступ браузеру. После фразы пауза примерно 1,05 секунды завершает запись;
текст распознаётся локальным Whisper, ответ генерирует Qwen2.5, озвучивает Silero.
Запись не идёт во время ответа AI. Включённый микрофон автоматически слушает следующую
реплику после окончания озвучки. Нажмите его повторно, чтобы выключить.
Без речи 15 секунд запись прекращается; предел одной реплики — 60 секунд.
При запрете микрофона можно писать вопросы текстом. «Повторить ответ» воспроизводит
последнюю реплику через локальный Silero, не через SpeechSynthesis или Google.

«Завершить»/закрытие диалога останавливает MediaRecorder, MediaStream, AudioContext,
проигрыватель и ожидающие запросы. Серверный Stop синхронизируется с текущим ходом runtime;
если действие уже подтверждено, Stop не откатывает его. Не гарантирует отмену вычисления
LLM на сервере, но запоздалый ответ не попадает в новое окно. При уходе со страницы
финализация отправляется best-effort с keepalive; без сети статус может остаться active.

## Контекст и история

`POST /api/shell/conversations` принимает ограниченную UI-модель, сервер создаёт снимок
AgentConfig и новый interaction. Рабочий активный агент и настройки старого интерфейса
не перезаписываются. Справочные агенты не имеют инструментов записи, подключения услуг
или выполнения кода; доступен только запрос человека, без реального соединения.
Роль «Сбор обращений» использует существующий безопасный runtime с user evidence
и отдельным подтверждением перед сохранением callback.

Кабинетные агенты/Q&A по-прежнему хранятся в браузере. При старте теста контекст и Q&A
передаются локальному серверу. Изменения применяются только к новым разговорам.
Fine-tuning, полноценного RAG и полной базы МТС нет. Неизвестные условия нельзя выдумывать.

`GET /api/shell/interactions` показывает только разговоры оболочки, включая закрытые окна.
Их расшифровки сохраняются в SQLite на этом компьютере. Старые примеры отделены отметкой
«пример», реальные локальные тесты — «AI». При недоступности серверной истории выводится
предупреждение, не ложное подтверждение сохранения.

Сам аудиофайл сервер не сохраняет: он обрабатывается для STT и освобождается; текст и
снимок контекста сохраняются. МТС, Groq, Edge TTS, Telegram и почта не вызываются в local-only.
Ссылки на официальную справку открываются только при отдельном переходе пользователя.
Не вводите реальные данные: это локальный прототип без многопользовательской изоляции.

## Передача коллеге

`local-voice.mjs` — транспорт и освобождение ресурсов. `track1/shell_api.py` — ограниченный
серверный адаптер; в `app.py` добавлено подключение его router. Остальные запросы используют
существующие `/api/chat`, `/api/transcribe`, `/api/speech`, `/api/application`.
`adapter.mjs` теперь отвечает только за браузерное хранение кабинета и старые примеры;
`demoAnswer` не используется в живом диалоге и не является fallback при ошибке модели.
Для серверного управления агентами, авторизации клиентов и реальных каналов нужна отдельная
интеграция. Standalone статический сервер без backend больше не обеспечивает разговор.
