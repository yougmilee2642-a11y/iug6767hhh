# Передача оболочки разработчику ядра

Обновление: базовый голосовой транспорт и локальная история уже реализованы.
Смотрите [LOCAL_AI.md](LOCAL_AI.md). План ниже сохраняется как исходный контракт;
серверное управление кабинетными агентами и авторизация пока не реализованы.

Сейчас работает только браузерный адаптер. Ниже контракт интеграции, а не описание
уже реализованного API. Нельзя объявлять текущую оболочку готовым клиентским кабинетом.

## 1. Данные и авторизация

В `app.mjs` репозиторий `api` создаётся через `createRepository` из `adapter.mjs`.
UI использует async-методы `listAgents`, `getAgent`, `saveAgent`, `listSessions`,
`saveSession`, `getSettings`, `saveSettings`. Заменить их HTTP-адаптером ядра, оставив
формат UI-моделей или добавив явный преобразователь.

Это НЕ простой переключатель localStorage → API. Добавить login/logout, серверную
сессию, owner_id, проверку владения всеми агентами/диалогами и серверную валидацию.
Демо-профиль убрать или заменить настоящим входом. Секреты не помещать в frontend.
Вместо демонстрационного графика показывать реальные метрики или честное пустое состояние.
Старую рабочую базу Callwise и реальных пользователей мигрировать отдельно, не импортировать
localStorage прототипа автоматически.

Agent UI-model: id, name, company, role, description, greeting, status, tone, voice,
speed, knowledge, qa[{id,question,answer,source}], icon, color.
Это облегчённая модель, НЕ полный AgentConfig текущего backend. Сценарии, поля,
инструменты, provenance и consent должен строить/проверять сервер.
Статус active в оболочке не означает публикацию, подключённый номер или платный тариф.

## 2. Голосовой транспорт

Точки замены в `app.mjs`: `openVoice`, `sendQuestion`, `finishVoice`, ветка `voice-mic`.
Сохранить UI-функции `setVoiceState`, `appendMessage`, `messageHTML` и состояния
ready → listening → thinking → speaking → ready; ended/error — терминальные/ошибочные.
Сейчас задержки в sendQuestion декоративные; demoAnswer возвращает статическую заготовку.
На боевом транспорте убрать эти задержки и не оставлять скрытый mock-fallback.

Для первой интеграции можно использовать существующие `/api/conversations`,
`/api/transcribe`, `/api/chat`, `/api/speech`, `/api/application`, но нужно проверить
их фактические payload/response, AgentConfig и права владельца. Разные URL на
разных origin требуют отдельного решения CORS/auth; предпочтительно один origin.
Для потоковой версии — согласовать WebSocket/WebRTC-протокол с ядром, не угадывать его.

При микрофоне: явное действие пользователя, getUserMedia только после него,
HTTPS/localhost, ошибка запрета доступа, индикация реальной записи, endpointing,
таймауты, отмена запросов, освобождение MediaStream/AudioContext и остановка аудио
на закрытии окна/смене агента. voiceJob сейчас защищает UI от запоздалого mock-ответа;
для сети добавить AbortController или session id и подтверждённую отмену.
Не воспроизводить два ответа одновременно. Хранение аудио и согласие на запись
должны быть отдельными бизнес-решениями, не следствием клика на микрофон.

События будущего транспорта, которые UI сможет отобразить:
state_changed{state}, transcript{role,text,turn_id}, answer{text,sources},
audio{url_or_stream}, error{code,message,retryable}, ended{session_id,result}.
Это предложенный UI-контракт; endpoint и формат аудио надо согласовать.

## 3. Знания МТС

QA_SEED — только три демонстрационных сценария. Никакого fine-tuning не выполнено.
Для первого пилота собрать проверенные официальные Q&A МТС Беларусь, очистить навигацию,
сохранить source URL и дату проверки, версионировать материалы, индексировать знания
и ограничить ответы этими источниками. Уточнить, какие темы агент вправе решать и
когда передаёт человеку; подключение услуг без разрешённого server-side действия запрещено.
Клиентский редактор Q&A не является доверенной системной инструкцией.
Не использовать материалы МТС России как замену белорусским правилам.

## 4. Чек-лист перед объявлением интеграции готовой

- Создание, редактирование, публикация и список агентов подтверждены сервером.
- Вход настоящий; клиент не видит чужие агенты и разговоры.
- Микрофон действительно захватывает речь; состояния связаны с transport events.
- Текст и звук ответа синхронизированы; Stop и закрытие освобождают ресурсы.
- Повтор/таймаут не дублирует запись и внешнее действие.
- Подтверждённый диалог появляется в серверной истории, не только localStorage.
- Пустые состояния и ошибки сети не заменяются демонстрационными ответами.
- Каналы отмечаются подключёнными только после реального серверного результата.
- Одобрены материалы, брендирование, доступ к данным и правила коммерческого использования.
# Актуальная связь с кабинетом (13.10.2026)

«Личный кабинет» и ссылки создания/знаний/истории открывают единый серверный кабинет Callwise (`/#overview`, `/#quick`, `/#knowledge`, `/#applications`). Старые `#cabinet/...` маршруты перенаправляются через `../cabinet-links.mjs`. Браузерный mock-кабинет больше не является активным рабочим интерфейсом.

Старые localStorage-записи не удаляются и не публикуются автоматически. В разделе помощников есть явный перенос черновика: компания, роль, приветствие, FAQ проходят короткий мастер, server validation, preview и подтверждение. История уже созданных shell-сессий доступна через общий список обращений. Примеры SEED_SESSIONS не становятся реальными метриками.

Публичное справочное голосовое демо по-прежнему использует `/api/shell/conversations`; оно не подключает услугу МТС. Основной кабинет использует сохранённые server-side AgentConfig.
