# Локальный benchmark распознавания речи Callwise

`P1-03` добавляет воспроизводимый офлайн-инструмент измерения локального русского STT. Он **не содержит эталонных аудиозаписей** и не запускает загрузку моделей. Для измерения нужны локальные WAV/аудио-файлы с разрешённым использованием и точные эталонные расшифровки.

## 1. Подготовьте manifest

Создайте JSON-файл, например `tests/voice-fixtures/manifest.json`:

```json
[
  {"id": "synthetic-01", "audio": "synthetic-01.wav", "reference": "Здравствуйте, чем могу помочь"},
  {"id": "synthetic-02", "audio": "synthetic-02.wav", "reference": "Назовите номер телефона для обратного звонка"}
]
```

Пути `audio` указываются относительно папки manifest. Используйте синтетические или явно разрешённые записи, а не реальные клиентские звонки без основания и согласия.

## 2. Запустите измерение

Из корня проекта:

```bash
python scripts/benchmark_voice.py \
  --manifest tests/voice-fixtures/manifest.json \
  --output voice-benchmark.json
```

Скрипт вызывает существующий `services.local_speech.transcribe_local`, который использует локальные веса Whisper/VAD. Нужные модели должны быть установлены заранее. Сетевой fallback не используется. По умолчанию в отчёт не попадают сами распознанные фразы.

В JSON отчёте есть:

- `wer_mean` — средняя доля ошибок по словам;
- `cer_mean` — средняя доля ошибок по символам;
- `latency_seconds_mean` и `latency_seconds_p95` — время распознавания;
- метрики по каждому `id`, без исходного текста.

Первый прогрев отделён в `warmup_seconds` и исключён из времени распознавания.
`--cold-start` включает его обратно и явно отмечает это в отчёте. Общий загрузчик
Callwise загружает также речевую модель TTS: её веса должны уже находиться локально.
Это ограничение загрузчика, а не измерение времени озвучки.

`wer_mean`/`cer_mean` — средние по записям; `wer_corpus`/`cer_corpus` — сумма ошибок,
делённая на сумму эталонных единиц всего набора. CER включает пробелы после нормализации.
Пунктуация, регистр и различие ё/е не учитываются. Для пустого корпуса знаменатель
не определён и корпусная метрика равна null. Идентификаторы должны быть строками.

В отчёт добавлены хеш набора и файлов, версии зависимостей, параметры модели,
Python и сведения об оборудовании. При сравнении зафиксируйте также версию локальных
весов. Здесь измеряется только STT: ожидание конца фразы, ответ LLM, TTS и начало
воспроизведения необходимо измерять отдельно. Этот инструмент не ускоряет модель.

`--include-text` сохраняет эталон и распознанный текст в отчёт; используйте только для синтетических/разрешённых данных. WER/CER — метрики качества набора, а не гарантия качества для всех акцентов, микрофонов и шумовых условий. Сравнивайте результаты на одном и том же наборе, версии модели и оборудовании.

## Текущий статус

Инструмент и unit-тесты метрик реализованы. **Реальные WER/CER/latency Callwise не заявляются:** в переданном архиве нет аудио-набора, а в проверочной среде не установлены локальные веса STT/VAD. После подготовки разрешённого набора benchmark нужно запустить на целевой машине и приложить JSON-отчёт.
