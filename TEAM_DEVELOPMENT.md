# Callwise: два разработчика, модели на одном компьютере

Да: исходный код и веса моделей — разные части проекта. Оба работают с одним кодом,
а тяжёлые модели могут оставаться только на ноутбуке Лёши.

## Общий код

Использовать приватный Git-репозиторий и отдельные ветки; либо передать чистый архив,
собранный `build-archive.ps1`. Архив содержит исходники и примеры настроек, но исключает
`.env`, `models/`, `downloads/`, `.venv/`, рабочую `data/`, журналы и базы.
У каждого разработчика собственная `.env` и среда зависимостей.
Не передавать токены Telegram, почты, пароли, реальные разговоры или регистрацию клиентов.

На компьютере коллеги без моделей доступна обычная разработка интерфейса и тесты
`python -m pytest -q`: тестовые провайдеры не требуют реальной LLM или речевых весов.
Без речевых моделей и запущенной LLM реальный локальный голосовой сценарий не заработает.
Для проверки своих изменений коллега передаёт ветку/патч Лёше, который запускает их
в своей копии. Нельзя одновременно редактировать одну рабочую папку или синхронизировать
живую SQLite-базу через облачную папку.

## Совместные проверки через ноутбук Лёши

Простой следующий шаг — открыть коллегe доступ к веб-приложению Callwise через приватную
VPN-сеть и HTTPS-прокси, например Tailscale Serve. Он использует твои модели через
твой backend, ничего не устанавливая у себя. Но это тест кода, который запущен на твоём
ноутбуке, а не автоматически тест его локальных изменений. Ноутбук, приложение и Ollama
должны быть включены; при выключении сервера AI недоступен.

Это пока НЕ настроено. В текущей копии:

- приложение слушает только `127.0.0.1:8000`;
- Ollama слушает только `127.0.0.1:11434`;
- `OllamaProvider` намеренно запрещает удалённый адрес LLM;
- без `CALLWISE_OWNER_PASSWORD` кабинет разрешён только на localhost.

При настройке доступа нужен пароль владельца от 12 символов, правильный `PUBLIC_ORIGIN`,
HTTPS и корректно доверенные proxy-заголовки. Проверить Host/Origin, вход, cookie и микрофон
с удалённого компьютера. Существующий вход общий для одного владельца, не отдельные роли
для двух разработчиков и не полноценная изоляция клиентов. Использовать синтетические данные.
VPN даёт сетевой доступ, но не делает приложение автоматически защищённым для продакшена.

Не открывать Ollama напрямую в публичный интернет: локальный API не требует аутентификации.
Публикация портов, установка VPN и выдача доступа требуют отдельной настройки; сейчас этого нет.

Если коллега должен запускать свой backend, но использовать твои модели, потребуется отдельный
защищённый AI-шлюз для LLM/STT/TTS и удалённый провайдер в коде. Простого изменения
`OLLAMA_BASE_URL` сейчас недостаточно; так обходить loopback-проверку нельзя.

Официальные источники:

- https://docs.ollama.com/faq — локальные модели, адрес сервера и хранение весов.
- https://docs.ollama.com/api/authentication — локальный API без аутентификации.
- https://tailscale.com/docs/features/tailscale-serve — доступ к локальному сервису внутри tailnet.
