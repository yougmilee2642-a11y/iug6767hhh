# Локальная текстовая модель Фокус

Целевая модель: `qwen3:4b-instruct` в Ollama, 4.02B, квантование Q4_K_M. Это именно Qwen3,
не Qwen3.5. Контекст Фокус ограничен 8192, выход — 384 токенами.
Для голосового диалога provider отправляет `think: false`; сообщения,
структурированный JSON и native tool calls идут через loopback `/api/chat`.
Облачного fallback нет. Бизнес-согласие, каталог, свободные слоты и подтверждение
записи проверяет серверный движок; замена весов не заменяет эти проверки.

Официальные источники: [модель Ollama](https://ollama.com/library/qwen3:4b-instruct),
[Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507),
[управление thinking](https://docs.ollama.com/capabilities/thinking).
В отличие от гибридной Qwen3-4B, Instruct-2507 не генерирует блок рассуждений.
При локальной проверке гибридного тега на Ollama 0.32.13 `think:false`, `/no_think`
и пустой thinking prefix не обеспечили стабильного короткого ответа.
Поэтому этот вариант не выбран для голосового runtime; увеличением лимита ошибка не скрывается.

## Установка и переключение

1. `ollama pull qwen3:4b-instruct`. Дождаться завершения и проверки digest самим Ollama.
2. `.venv/Scripts/python.exe scripts/check-local-llm.py --model qwen3:4b-instruct`.
   Это реальные запросы к модели: русский ответ с известной ценой, native вызов
   вымышленного read-only инструмента и его результат, структурированное извлечение.
   Дополнительно проверяет, что модель действительно не генерирует рассуждения,
   а не просто скрывает их после генерации. Тест не создаёт бизнес-запись
   и не доказывает качество на всех сценариях.
3. В `.env` задать `OLLAMA_MODEL=qwen3:4b-instruct`, остальные настройки не менять.
4. Перезапустить только сервер Фокус. Проверить `/api/health`: `model`,
   `llm_ready`, локальный режим и готовность речи. `ollama ps` показывает фактическое
   устройство исполнения; параметр в `.env` сам по себе не доказывает GPU.
5. Прогнать `scripts/rehearse-booking-engine.py` во временной базе и
   `scripts/smoke-shell-local.py` для синтетического HTTP WebM → ASR → модель → TTS.
   Последний тест сохраняет только вымышленный незавершённый диалог в локальной истории.
6. Лишь после успешной проверки: `ollama rm qwen2.5:3b`.

Ollama хранит веса в собственном кеше, а не дублирует их в проекте. `start-local.ps1`
уважает явно заданный нестандартный `OLLAMA_MODELS`, иначе использует обычный кеш.
Устаревший путь `models/ollama` из прежнего запуска автоматически заменяется
обычным кешем, чтобы после удаления старой копии приложение не искало веса там.
Не удаляйте каталог `blobs` целиком: блоки могут принадлежать другим моделям.
Старую отдельную копию Qwen2.5 в `models/ollama` нужно удалять только по её
manifest и после проверки, что её блоки не используются другими manifest.

## Границы проверки

Серверные сценарии записи могут обходиться без LLM: успешная запись — не
доказательство, что новая модель сама правильно распознала намерение.
Native tool smoke проверяет отдельно модельный протокол. Микрофон, шум,
произношение, многозначные фразы и свободный FAQ требуют отдельного набора оценок.
Смена Qwen не меняет модели распознавания и озвучки и не обещает ускорения.
Первый холодный запуск включает загрузку весов; его нельзя сравнивать с прогретой моделью.
