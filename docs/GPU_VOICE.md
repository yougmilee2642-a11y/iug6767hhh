# GPU-речь и разговорное демо — 14 октября 2026

## Поведение демо

В оболочке МТС один старт → техническое согласие → разрешение браузера на микрофон → приветствие → автоматическое прослушивание. После секунды тишины реплика отправляется на распознавание; после озвученного ответа AI запись следующей реплики начинается сама. Кнопка микрофона нужна для отключения/возобновления, а не для каждой фразы. Если устройство недоступно, остаётся текст. Отказ не включает микрофон.

Это turn-based веб-разговор, не SIP/телефония и не full-duplex: во время озвучки помощник не распознаёт перебивание. Существующие ограничения по отсутствию речи, ошибкам и завершению сохраняются. Начало разговора не должно автоматически посылать за пользователя выбранный пример вопроса.

## Устройства

- Ollama Qwen2.5:3b: до изменений `ollama ps` уже показывал 100% GPU, контекст 8192.
- Whisper Small: код поддерживает CUDA `int8_float16` и CPU `int8`.
- Silero v5_ru: код поддерживает CUDA и CPU; WAV возвращается с GPU через CPU-копию.
- Silero VAD ONNX, декодирование, браузерный захват, HTTP и бизнес-логика остаются на CPU. Это не означает CPU-инференс Whisper/Qwen.
- Статус `/api/health.local_speech` содержит фактические загруженные устройства, compute type и warmed. Значения конфигурации сами по себе не доказывают GPU-инференс.

`auto` использует доступный CUDA runtime; `cuda` при отсутствии runtime выдаёт ошибку, а не молча переключается на CPU. Настройки меняются только с перезапуском сервера:

```env
LOCAL_STT_DEVICE=cuda
LOCAL_STT_COMPUTE_TYPE=int8_float16
LOCAL_TTS_DEVICE=cuda
```

14 октября установка завершена: официальный wheel проверен по SHA256, PyTorch 2.11.0+cu128 и torchaudio установлены в `.venv`. Реальный синтетический GPU-прогон `proof/phone-gpu/speech-check.json` подтвердил Whisper и Silero на CUDA RTX 5060 Laptop GPU. Эти значения включены в рабочем `.env`. VAD остаётся на CPU. Это не тест человеческого микрофона или телефонной линии.

## Установка в среду проекта

CUDA PyTorch 2.11.0 и соответствующий torchaudio берутся из официального индекса cu128, не устанавливаются глобально. Зависимости: `requirements-local-gpu.txt`. На Windows библиотеки cuBLAS/cuDNN из torch/lib подключаются только к текущему процессу.

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-local-gpu.txt
```

Для медленного источника есть `scripts/download-torch-cuda.py`: скачивает официальный Windows/Python 3.11 wheel частями, сохраняет прогресс, проверяет SHA256 из официального индекса **до установки**. Файл `.partial` не пригоден для установки. Завершённый wheel можно передать pip вместо повторной загрузки torch.

Прогрев выполняет не только загрузку весов: синтетическая фраза проходит TTS, VAD и Whisper, до пользовательского разговора. Qwen также прогревается существующим безопасным startup-запросом без бизнес-действий.

## Измерение

`scripts/benchmark-voice.py --output proof/voice-gpu-after.json --runs 3` проводит вымышленные разговоры через localhost, явно принимает техническое демо-согласие. Не включает человеческий микрофон, паузу endpointing или проигрывание WAV, не пишет в CRM и не проверяет шум.

CPU-базовая линия: `proof/voice-cpu-before.json`, две короткие синтетические реплики. STT 1,381–1,463 с, LLM 0,564–0,943 с, TTS 0,039–0,040 с, последовательная серверная цепочка 1,984–2,446 с. Это не p50/p95 и не обещание задержки каждого звонка.

Прямой GPU-прогон после прогрева: 3 синтетические фразы, STT 0,217–0,254 с, TTS 0,018–0,031 с. Это отдельные локальные этапы без HTTP, endpointing и проигрывания. Нельзя объявлять эти числа полной задержкой голосового ответа.

После включения GPU и перезапуска на 8000 HTTP-прогон `proof/voice-gpu-after.json`: 3 успешных синтетических разговора, STT 0,269–0,461 с, LLM 0,555–0,798 с, TTS 0,025–0,034 с; последовательная серверная цепочка 0,850–1,292 с. Пауза окончания речи (~1 с), захват микрофона и проигрывание не включены. Ответ во всех прогонах одинаковой длины — 30 символов. Это маленькая выборка, не нагрузочный тест и не оценка p95.

Рабочий health после перезапуска подтвердил stt_device=cuda, tts_device=cuda, warmed=true; Ollama qwen2.5:3b — 100% GPU. Все модели одновременно занимали примерно 3227 MiB из 8151 MiB. После установки: 592 Python-теста прошли, 12 пропущены, pip check — без нарушенных зависимостей. Правки ядра коллеги не отменялись.
