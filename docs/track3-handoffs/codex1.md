## Экраны и поведение

- **Обзор:** реальные `/overview` metrics, формула, датированный источник, warnings и честный null. При входе в раздел выполняется обновление. Просроченное поручение открывает вкладку задач исходной встречи. Источники KPI показывают числитель/знаменатель, период, снимки и исходные задачи.
- **Встречи:** прежние создание, документы, поиск, справка, материалы, сопоставление говорящих и цитаты. Добавлены редактирование темы/участников, open_tasks/task_questions предыдущих встреч и QA в контексте встречи. Дата из datetime-local конвертируется в aware ISO в явно выбранной IANA-зоне; неоднозначное/отсутствующее DST-время отклоняется.
- **Календарь:** тестовый справочник, диапазон, зона, длительность и слоты. Preview показывает реальные дату/время, зону, участников и тексты тестовых приглашений. Только отдельное подтверждение вызывает `/calendar/confirm`; cancel/Escape отменяет confirmation. При 409 на preview или confirm есть обновление слотов с сохранёнными параметрами. Реальная почта не обещается: серверный provider mock/local_outbox.
- **Протокол:** summary с verified/needs_clarification, решения, предложения с исходами, поручения, риски, открытые вопросы. Неизвестные исполнитель/срок заметны; правки сохраняются явно. Перед созданием задач — итоговый список выбранных поручений, затем явное подтверждение. Ответы created/already_confirmed объединяются по ID без дублей. Просмотр следующей повестки не создаёт встречу; создание осталось отдельным подтверждаемым действием.
- **Знания:** глобальный/meeting context, вопрос, только claims с источниками, дата и настоящая цитата. Свободное поле answer не используется для дополнительных утверждений; HTML сервера не исполняется. Insufficient_data отображается как «Оснований не найдено». Feedback useful/incorrect с комментарием отправляется только кнопкой. Для prep/summary/items/tasks feedback свёрнут, чтобы не загромождать экран.
- **Задачи:** изменение статуса, исполнителя и срока через server preview before/after → confirm с одним idempotency_key на попытку. PATCH больше не используется. Отмена не меняет задачу; локальный незавершённый ввод сохраняется в памяти текущей вкладки и привязан к пользователю.
- **Роли и сессии:** capabilities из `/me`, без определения прав по должности. На 401 очищаются закрытые ответы, документы, цитаты и результаты; несохранённый ввод восстанавливается только тому же повторно вошедшему пользователю. На 403 объясняются права и перечитывается `/me`. Явный выход очищает все черновики. Пароли не кешируются. Поздний ответ старой сессии игнорируется; QA также связан с исходным контекстом. Запись останавливается при выходе, её очередь не переносится в новый профиль.
- **Доступность:** native dialog, label, focus trap, Escape и возврат фокуса. Loading/empty/error/retry, защита от повторного подтверждения, предупреждение beforeunload. Долгая генерация блокирует свою кнопку и не блокирует навигацию; повторное открытие раздела не запускает вторую генерацию.

## API-наблюдения и ограничения

1. На исходной базе создание с naive scheduled_at несовместимо с новым ядром: требуются offset или timezone. UI теперь отправляет оба явно; 09:00 Europe/Minsk → 06:00Z, проверено браузером.
2. Исходный PATCH `/tasks/{id}` нового ядра даёт `409 confirmation_required`. UI целиком переведён на preview/confirm; отдельный тест запрещает этот PATCH.
3. `Utterance` не содержит собственного created_at/source_at. В панели честно подписана **«Дата встречи»**, а не выдуманная дата реплики. У документа source_at — дата загрузки, не дата публикации. У QA/KPI отображается server source_at.
4. Prep open_tasks приходит после формирования prep; когда prep=null, сервер не возвращает эту цепочку. UI не придумывает её и не выполняет скрытую генерацию ради отображения.
5. Качество/скорость реальной Ollama и физического микрофона не проверялись здесь. Проверка настоящей модели/данных остаётся интеграционной оценкой серверных исполнителей. Прямой probe `127.0.0.1:11434/api/tags` в этой среде вернул connection refused; скрытого fallback нет. Автоматическое определение говорящих не обещается.
6. Публикация здесь означает push своей ветки и PR в текущий GitHub-репозиторий, как требует задание. Слияние в main и отдельный production-хостинг не выполнялись.


## Дополнительная проверка после PR

Восемь новых проверок сначала воспроизвели ошибки (все восемь падали на предыдущей реализации), затем прошли после исправления. Остальные новые сценарии покрывают протокол, поздние ответы при навигации, зоны времени и безопасные повторы после сбоев. Итоговый набор — **35 браузерных сценариев**, включая первоначальные 18.

- PATCH темы/участников подтверждает только отправленную версию. Ввод, набранный пока запрос выполнялся, остаётся черновиком, в том числе после смены вкладки.
- При изменении диапазона, зоны, длительности или календарных участников прежние слоты сразу удаляются. Поздний ответ slots и preview больше не открывает устаревшие варианты или диалог поверх другого раздела. Справочник и выбранные участники сохраняются при возврате на вкладку; до загрузки справочника поиск отключён, организатор явно включён.
- После успешного calendar confirm сбой GET встречи не оставляет кнопку повторного подтверждения. Retry обновляет только данные; эффект не выполняется повторно. Дата в заголовке и список встреч обновляются после фактического назначения.
- В task preview отправляются только изменённые поля. Изменение одного статуса больше не отправляет due:null и не стирает due_text. В настоящем HTTP-smoke проверено сохранение «после согласования»; предпросмотр сообщает, что срок словами сохраняется.
- Один `protocolPayload` используется редактором, предпросмотром и PUT. Назначение новой даты очищает прежний срок словами в поле и запросе; явно введённое новое уточнение сохраняется. Пустая формулировка не отправляется, фокус возвращается в проблемное поле. Предупреждения исполнителя/срока и исход предложения обновляются сразу. Выбор поручений сохраняется при смене вкладки.
- Пока модель обновляет черновик протокола, поля этого протокола защищены от новых правок, которые результат генерации заменил бы. Навигация по остальному приложению доступна; после завершения поля снова доступны. Отправленные ранее правки сохраняются перед генерацией.
- Завершение logout ожидается до нового login: поздний ответ выхода не может очистить cookie нового пользователя. Навигация и демо-входы отключены на соответствующем этапе. Закрытый заголовок источника также очищается; диалоги удаляются при смене сессии синхронно.
- Поздний ответ поиска не может заменить результаты более нового вопроса; loading/error/retry отделены от пустого результата. Позднее открытие встречи не отменяет уже выбранный раздел задач.
- Два поля ручного сопоставления говорящего имеют отдельные подписи и ключи черновика; введённое имя не теряется при смене вкладки. Алгоритмы речи не изменялись.

Настоящий HTTP-smoke усилен конкурирующим calendar confirm: другой запрос занимает выбранное время после открытия предпросмотра, браузер получает 409, обновляет слоты и успешно подтверждает новый. Также проверены дата в заголовке и сохранность due_text после task confirm. Последние скриншоты протокола на 360 px визуально просмотрены. В последнем HTTP-прогоне использованы серверы: core `cd06b4d`, knowledge `9330edc`; пользовательский код и чужие ветки не менялись.


В финальном наборе также проверены:
- Карточка и заголовок встречи отображают время в явно подписанной зоне встречи; календарная дата срока не сдвигается даже при зоне браузера Pacific/Kiritimati. Проверены Asia/Tokyo и Europe/Minsk.
- Retry поиска слотов использует уже исправленные пользователем параметры, а не ревизию первоначально неудачного запроса.
- После успешного создания встречи-продолжения ошибка обновления списка не оставляет повторное создание доступным в диалоге. Retry загружает список и не вызывает POST создания снова.
