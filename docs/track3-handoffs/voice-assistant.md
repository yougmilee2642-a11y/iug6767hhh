# «Фокус» — голосовой помощник руководителя (MVP)

Ветка `voice-assistant`, основана на `main` `35ba34c`. В `main` не влито: PR открыт для просмотра.

## Что умеет

- **Кнопка «Спросить голосом»** в шапке `/meetings` (или Alt+V): нажал, сказал вопрос, нажал ещё раз.
  Без включённого режима активации микрофон работает только в это время. Esc отменяет запись.
  Если микрофона нет, можно написать вопрос в поле панели «Фокус».
- **«Привет, Фокус» / «Окей, Фокус»**. Режим включается в панели после явного согласия: «все в комнате знают, что Фокус слушает…».
  - Вопрос можно сказать сразу за фразой («Окей, Фокус, какой бюджет кампании?») или после короткого сигнала.
  - Пока звучит ответ, режим на паузе, чтобы помощник не услышал себя.
  - Режим выключается сам, когда начинается запись встречи или меняется профиль.
- **Ответ**: голосом звучит одна короткая фраза с источником и датой, полный ответ с цитатами показан на экране.
  - «Оснований не найдено» озвучивается честно.
  - Длинная цитата (больше 220 символов) не обрезается: голосом звучит «ответ длинный, он на экране» и источник.
- **Только чтение**. Вопрос направляется в существующие сервисы: знания (`knowledge.service.answer`, как `POST /api/meet/qa`) или обзор (`management.service.build`, как `GET /api/meet/overview`).
  - Маршрут выбирает регулярное выражение, а не модель. Новой точки обращения к LLM нет.
  - Команды «поставь / создай / пригласи / перенеси / отмени…» и «можешь / нужно + инфинитив» получают отказ: «Голосом я ничего не создаю и не меняю. Откройте предпросмотр… и подтвердите на экране». В панели есть кнопка перехода в нужный раздел.

## Режим «не озвучивать» (включён по умолчанию)

Права проверяются по пользователю, а динамик слышат все в комнате. Поэтому фраза звучит, только если каждый слушатель мог бы увидеть то же самое сам.

- **Слушатели**: на странице встречи — владелец и участники с доступом; вне встречи — все пользователи системы.
- **Знания**: каждый документ-источник должен быть доступен каждому слушателю.
- **Обзор**: фраза пересчитывается правами каждого слушателя на одном снимке БД и должна совпасть дословно.
- Иначе ответ показывается только на экране: `speak: false`, `spoken: null`, текст причины.
- Флажок «Я один в комнате» снимает ограничение для одного вопроса.

## API

| Метод | Назначение |
|---|---|
| `POST /api/meet/voice/ask` `{text, meeting_id?, speak_private?}` | Возвращает `{route: knowledge\|overview\|action, status, answer, display, spoken, speak, silent_reason, open_page}`. Права роли (`qa.ask` / `overview.read`) и доступ к встрече проверяются на сервере. Аудит `voice.ask` пишет маршрут, `spoken`, `private` и источники, но не текст вопроса и не ответ. |
| `POST /api/meet/voice/transcribe` (wav) | Только локальный ASR (`CALLWISE_LOCAL_ONLY`/`AI_PROVIDER=ollama`), иначе 503 `local_asr_required`: звук внутреннего вопроса не уходит в облако. До 5 МБ, ничего не сохраняет, `Cache-Control: no-store`. |
| `POST /api/meet/voice/wake` (wav до 256 КБ ≈ 8 с при 16 кГц) | Проверка фразы активации. Работает только для клиента с loopback-адреса без заголовков прокси (компьютер в комнате) и с локальным ASR. Возвращает только `{wake, question}`: чужая речь не возвращается, не журналируется и не попадает в аудит. |

Озвучка — существующий `POST /api/speech` (локальный Silero).

## Замеры (реальные модели, демо-данные, 11.11.2026)

Окружение: локальные Ollama `qwen2.5:7b`, ASR T-one/GigaAM, TTS Silero, демо-БД `scripts/seed_meetings_demo.py`.
Звук вопроса синтезировался Silero и передискретизировался в 16 кГц моно, как отправляет браузер.

| Фраза | ASR + активация | Ответ | TTS | Результат |
|---|---|---|---|---|
| «Окей, Фокус, какой общий бюджет кампании?» | 0,85 с | 1,6 с | — | knowledge, «Общий бюджет — 4,2 млн рублей», **не озвучено**: документ виден только Ирине |
| «Привет, Фокус, сколько просроченных задач?» | 0,79 с | 0,03 с | 0,11 с | overview, озвучено |
| «Привет, Фокус, поставь задачу Петру на пятницу.» | 0,73 с | 0,02 с | 0,11 с | action, отказ озвучен, записей нет |
| «Окей, Фокус, какой гайд по бренду?» | 0,67 с | 1,8 с | 0,09 с | knowledge, документ общий — озвучено |
| «Привет, Фокус.» | 0,58 с | — | — | активация, ждёт вопрос |
| «Давайте сделаем фокус на браке.» | 0,67 с | — | — | не активировано |
| «Привет, Пётр, как фокус-группа?» | 0,62 с | — | — | не активировано |

Через интерфейс:

- «Какие риски по запуску Орбиты?» → честное «оснований не найдено»: ответ 13 с (первый вызов модели после старта), озвучка 0,45 с;
- повторные вопросы к знаниям → 1,6–2,2 с.

Итого от конца фразы до начала звука: около 2,5 с для вопроса к документам и около 1 с для обзора и отказа. Сюда добавляется 0,7 с тишины, после которой фраза считается законченной.

## Слово активации и ложные срабатывания

«Фотик» не подходит: в корпусе встреч проекта 61 из 281 реплики (22 %) содержит «фото…». «Фокус» — обычное слово («фокус на сроках»), поэтому срабатывает только сочетание из двух слов **в начале реплики**: «привет/окей/ок + фокус».

- Отсекаются: «Фокус на сроках», «сделаем фокус на браке», «Окей, фокусная группа», «привет, фокус-группа» внутри фразы.
- Возможное ложное срабатывание: реплика, начинающаяся с «Окей, фокус в том, что…».

Как мерили и как мерить дальше:

1. **Текст** (сделано): по всем 281 репликам демо- и оценочных стенограмм трека 3 (33 файла) — 0 срабатываний, 0 реплик со словом «фокус».
   Скрипт прогоняет `meetings.voice.wake_match` по каждой фразе. Корпус маленький, это только нижняя граница.
2. **Звук, ложные срабатывания** (нужно до включения по умолчанию): записать не меньше 8 часов обычных встреч в переговорной с согласия участников и прогнать через `POST /api/meet/voice/wake` теми же сегментами, что режет браузер (VAD, пауза 0,7 с, до 6 с).
   - Метрика — срабатываний в час. Цель — не больше 1 за 8 часов.
3. **Звук, пропуски**: 5–10 человек по 20 раз произносят обе фразы с разного расстояния и при шуме.
   - Метрика — доля распознанных активаций. Цель — не меньше 90 %. Отдельно смотреть, как ASR пишет «Фокус» («фокс», «покус»): при необходимости добавить варианты в `WAKE`.

Запасные варианты фразы, если замеры покажут проблему: «Окей, Фокус» без «привет» или более редкое имя («Сова», «Компас») с той же схемой из двух слов.

## Ограничения MVP

- Детектор активации — VAD в браузере и короткие сегменты в локальный ASR, а не отдельная KWS-модель.
  Пока режим включён, ASR распознаёт всю речь в комнате: это нагрузка на CPU/GPU. Поэтому режим необязательный, требует согласия и работает только на компьютере в комнате.
- Маршрутизация по ключевым словам: вопрос о «задачах» уходит в обзор, даже если он про документ. Если упомянут документ или регламент, вопрос уходит в знания.
- В Browser pane нет микрофона. Проверены резервный текстовый ввод и полный путь API на реальных моделях с синтезированным звуком.
  Живой микрофон нужно проверить в Chrome на компьютере в комнате.
