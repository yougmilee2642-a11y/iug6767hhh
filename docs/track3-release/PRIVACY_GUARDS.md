# Границы обработки моделью · v2

Это описание реализованных проверок, не утверждение о завершении всего E11.
Все наблюдения в этой среде получены с дублёрами; живые модели не запускались.

## До провайдера

`meetings/privacy.py:private_json` вызывается из всех пяти стадий `extract` и
knowledge QA. Маскирование выполняется до `provider.json`, включая подставленные
дублёры: международные телефоны +…/8 0xx, e-mail, карточные номера, паспортные номера,
УНП по метке, адреса по шаблонам, известные имена клиентов из CRM без учёта регистра/повторных пробелов.
Имена сотрудников не заменяются списком клиентов: они нужны для атрибуции задач.
Источники в БД не перезаписываются маскированным текстом.

Модельные результаты не проходят автоматическую обратную подстановку. Кнопка
источника открывает оригинал только после повторной проверки прав пользователя;
проверенные цитаты собираются из разрешённого оригинала. Токены действуют только
внутри одного обращения и не дают доступа к другим объектам.

Это детерминированные шаблоны, не полноценная система распознавания всех видов
ПДн. Скрытые Unicode-символы удаляются перед проверкой; бизнес-идентификаторы,
ISO-даты, суммы BYN и системные инструкции сохраняют смысл. Неизвестные имена,
склонения, нетипичные адреса и намеренно изменённое написание требуют отдельной
проверки хоста перед работой с реальными данными. Продуктовый набор синтетический.

## Доступ, намерения и недоверенные источники

- SQL выбирает разрешённые источники до ранжирования, лимитов и агрегации.
  `admin`/`auditor` не читают содержимое; `secret` исключён из контекста модели
  для любого пользователя. Право скачать оригинал не разрешает передать его AI.
- QA и голос проверяют запрещённые пользовательские намерения: кадровые решения,
  платежи, подписание договоров, раскрытие зарплат/ПДн. Возвращаются отказ и
  ответственный человек; модель и операции записи не вызываются. Детектор
  ограничен проверенными формулировками; будущие адаптеры обязаны дополнительно
  ограничивать набор допустимых операций.
- Корпус инъекций покрывает 15 вариантов в TXT/MD/DOCX/XLSX/CSV/EML/HTML/PDF,
  стенограмме/звонке, названии и имени файла; есть скрытый Unicode. Инструкции
  источника не являются пользовательской командой.
- QA предлагает только проверяемые выдержки; инструкции не могут стать claims.
  Заголовок/имя файла с распознанной инъекцией исключаются. Если фрагмент содержит
  и полезный факт, и инъекцию, исходный текст может передаваться как недоверенные
  JSON-данные; модель выбирает только разрешённые ID безопасных выдержек.
  Независимый валидатор не исполняет поля tool/arguments или неизвестные ID.
- В подготовке сохранён прежний путь делимитированных недоверенных документов;
  каждый предлагаемый факт проходит проверку цитаты. В протоколе реплики с
  распознанной инструкцией ассистенту исключаются; действия из них не создаются.

## Аудит

Логируются вход/неуспешный вход/выход, чтение/поиск/QA, подтверждения, отмены,
отказы, права и делегирование. В QA хранятся маскированное представление вопроса
и хеш; исходный вопрос не сохраняется. Голосовой аудит сохраняет только длину/хеш
вопроса, без его формулировки. Аудитор/директор видят общий журнал,
руководитель — журнал отдела; legacy-права сохраняются. Отказ пишется отдельной
транзакцией после отката основной операции.

UI журнала поддерживает фильтры пользователя, действия, объекта, результата и
aware ISO-даты; CSV содержит только служебные поля и защищён от формул. Экспорт
сам фиксируется в аудите. Полное расписание хранения/удаления ещё относится к
E11.5; см. [DATA_POLICY.md](DATA_POLICY.md).
