# CRM и ERP: локальная имитация

Реального подключения к Битрикс24, Mary или ERP нет. `MockCRM` читает
синтетические витрины выбранной SQLite-БД. Сетевых вызовов, вебхуков и секретов
этот адаптер не использует. Контракт находится в
`meetings/connectors/contracts.py`; реализация — `mock.py`.

## Проверяемый путь

1. Запустить по `V2_QUICKSTART.md`, войти `prod_head` / `prod_head-demo`.
2. «Задачи» → «Отправить в Битрикс24 · mock». Проверить текст, сопоставленного
   сотрудника, срок (может отсутствовать), приоритет и цитату.
3. «Отмена» закрывает токен; ни outbox, ни объект CRM не создаются.
4. После нового preview → «Подтвердить» появляется `mock:task:…` и статус.
   Повтор confirm возвращает тот же результат. Одновременные подтверждения
   сериализуются транзакцией; две разные карточки одной задачи не дают дубль.
5. «Статус CRM · mock» читает состояние, не меняя статус исходной задачи.
6. В протоколе → «Прикрепить протокол к CRM · mock». Выбрать доступную сделку
   либо уже экспортированную задачу. Передаются только подтверждённые пункты
   с проверяемыми репликами; снова отдельный preview → confirm.
7. `admin` / `admin-demo` → «Интеграции» → «Проверить соединение» выполняет
   чтение mock-адаптера, показывает результат и пишет аудит. Прямой адрес:
   `/meetings#integrations`. Администратор не получает содержимое экспортов.

`crm.write` есть у director/head; employee получает 403 и запись отказа.
Head экспортирует свой/делегированный отдел. Перед confirm заново проверяются
права, актуальная роль, секретность встречи, версия, содержимое и цитаты,
доступ к связанным сущностям и действующее сопоставление исполнителя.
`secret` не экспортируется. Нет сопоставления — 422 `employee_mapping_required`,
никакой отправки. Срок не угадывается. Ограниченные кадровые/платёжные/договорные
поручения и обнаруженные инъекции не передаются; поля проходят ограниченный
PII-фильтр, описанный в `PRIVACY_GUARDS.md` (это не универсальный NER).

Явно упомянутые `PP-0000-00000` / `client-0000` распознаются в тексте/цитатах.
В подтверждённой задаче сохраняются только доступные существующие связи.
Кнопка заказа открывает карточку ERP, историю статусов и доступные обращения;
ACL применяется до чтения. Номер из текста не означает права на карточку.

## Сбои и актуальность

Задать env **до запуска** (или перезапустить сервер после изменения):

| Переменная | Поведение |
|---|---|
| `MOCK_CRM_FAULT=timeout` | preview/read: 503 unavailable; если таймаут возник после preview, confirm сохраняет outbox `uncertain`, 503; записи mock нет |
| `MOCK_CRM_FAULT=down` | источник недоступен; после preview confirm сохраняет `failed`, 503 |
| `MOCK_CRM_FAULT=stale` | данные старше 7 дней, предупреждение в preview/карточке/обзоре |
| `CRM_STALE_AFTER=86400` | порог устаревания в секундах, по умолчанию 24 часа |

Существующие записи `uncertain`/`failed` не пересылаются автоматически,
даже если убрать fault и повторить confirm либо создать новый preview.
Нужна ручная сверка. Интерфейса разрешения спорной операции пока нет.
В обзоре при down/timeout сохранённые витрины остаются видны с предупреждением;
они не объявляются свежими данными доступного источника.

Нормализованные значения содержат `source_id`, `fetched_at`, `as_of`, `stale`.
`fetched_at` — время чтения; оно не заменяет дату исходного снимка.
Карточка клиента выдаёт псевдоним по ID, без контактных полей.

## Границы реализации

Миграция 11 добавляет `integration_outbox` и `mock_crm_objects`, не изменяя
миграции 1–10. Outbox хранит хеш и маскированный preview, подтверждающего,
время, статус, ссылку/код ошибки. Он создаётся **только после confirm**.
Объект mock и outbox находятся в одной транзакции одной БД. Это проверяет
локальную идемпотентность; не доказывает exactly-once в распределённой CRM.
Таймаут — инъекция сбоя на границе записи, не измерение сети.

Пока поддерживается одна отправка задачи и одно прикрепление протокола встречи.
Автоматическое обновление отправленной задачи/рассылка разным получателям,
сверка неопределённой операции, импорт сотрудников из отдельного портала,
реальный Bitrix24, Mary/1С/HR-адаптеры остаются P1/P2. Таблица уже имеющихся
сопоставлений — не результат внешней синхронизации. API Bitrix24 здесь не
реализован и не объявляется проверенным; перед его реализацией нужно отдельно
сверить официальные методы и поля. Новых библиотек этот блок не добавляет.
