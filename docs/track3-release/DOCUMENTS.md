# Документы · версии и проверяемые выдержки

Срез E6.2–6.5. Все данные остаются в выбранной SQLite, новых зависимостей нет.

## Использование

«Знания» → «Документы · версии и источники». Можно загрузить несколько файлов
последовательно, указать тип, конфиденциальность, отдел и aware-даты. Сотрудник
загружает только в свой отдел с уровнем department; директор может выбрать отдел.
При частичной ошибке уже загруженные документы остаются, счётчик показывает прогресс;
повтор всей пачки может создать новые самостоятельные документы.

Карточка: «Открыть источник», «Кратко», «Версии / сравнить». «Новая версия» доступна
владельцу с documents.upload; чтение чужого документа само по себе её не разрешает.
Форма → предпросмотр → подтверждение. Отмена удаляет временные байты. Доступ,
отдел, название и тип наследуются; ни старые фрагменты, ни привязки встреч не меняются.
Новую редакцию к встрече нужно прикрепить явно. Чтобы задать актуальный scope,
старую можно открепить обычным действием в материалах встречи.

## Контракт

| Действие | Маршрут относительно /api/meet |
|---|---|
| Новая редакция, файл и authored_at/valid_until | POST /documents/{id}/versions/preview (multipart) |
| Подтверждение | POST /documents/{id}/versions/confirm с confirmation_id/idempotency_key |
| История, отдельно проверенная ACL каждой редакции | GET /documents/{id}/versions |
| Текстовые изменения с исходными цитатами | GET /documents/{id}/compare/{other_id} |
| Выдержки с цитатами | GET /documents/{id}/summary |
| Все доступные редакции в поиске | GET /search?q=…&include_history=true |
| История в QA | POST /qa с include_history: true |

Повтор подтверждения возвращает прежний результат. Конкурентные подтверждения
сериализуются. Изменение ACL, владельца, метаданных или появление другой редакции
после preview → 404/409 без новой версии. Срок токена — 15 минут. Версия — отдельная
строка с supersedes_id; оригинал и F-id старой цитаты остаются неизменными.

Поиск и QA по умолчанию исключают заменённые доступными редакциями документы
до FTS/BM25. Недоступная редакция не влияет на ранжирование и не раскрывается
через флаг «заменён». Историю разрешено читать частично: чужие строки скрыты,
недоступный supersedes_id не возвращается. Admin/auditor не получают содержимое.
Secret доступен владельцу вручную, но исключён из сводки и сравнения.

QA повторно проверяет актуальность после генерации: новая редакция во время
запроса → 409 stale_sources. Сохранённый ответ остаётся историческим: источники,
их контекст и ACL перепроверяются, рядом показывается свежее предупреждение
о замене/истечении valid_until. Такие же предупреждения есть в сохранённой
подготовке встречи. Ответ не переписывается задним числом.

«Кратко» — первые пять подходящих фрагментов (может быть меньше), дословно,
с источниками, без модели. Это извлечение, не полноценная смысловая сводка;
в интерфейсе прямо указано ограничение. Инъекции не становятся claims.
Сравнение — SequenceMatcher по целым фрагментам, не word diff и не толкование
изменений договора; максимум 2000 фрагментов на пару. Цитаты обоих документов
открываются через существующую панель источника.

## Проверка и ограничения

`tests/test_track3_document_versions.py`: миграция v12→13 без потери данных,
пустая БД, cancel/replay/гонки, разные роли, отзыв доступа, метаданные, даты,
повреждение файла, истёкший токен, история/секреты/инъекции/QA/сохранённая справка.
`v2_http_smoke.py`: тот же путь через сервер и после restart.
`v2_ui_check.py`: загрузка, выдержки, отмена, confirm, история и diff в браузере.

Полный semantic-summary, карточки противоречий, извлечение обязательств,
масштабирование индекса и планировщик очистки остаются вне этого среза.
Браузерный прогон локально заблокирован socket policy; требуется результат CI.
