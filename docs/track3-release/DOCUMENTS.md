# Версии документов, выдержки и сравнение

В «Знаниях» раскрыть «Документы · версии и источники». Фильтр по названию,
переключатель заменённых версий, исходный файл, «Кратко», «Версии / сравнить» работают
без модели. Владелец с `documents.upload` может загрузить новую редакцию:
выбрать файл и необязательные aware ISO даты → предпросмотр → подтвердить.
Отмена не создаёт документ; при повторном открытии редактора файл и даты
сохраняются в памяти до подтверждения или смены сессии.

## Правила

- Предыдущий файл, фрагменты и их ID неизменны. Новая запись имеет
  `version+1`, `supersedes_id`, свои фрагменты, дату загрузки и SHA-256.
  Отдел, конфиденциальность, тип и ACL наследуются. Изменить чужой файл через
  версию нельзя, даже если он доступен директору. Admin/auditor не видят контент.
- Preview не создаёт документ: BLOB временно хранится отдельно. Confirm связывает
  файл, права, метаданные, содержимое и фрагменты исходника с предпросмотром.
  Изменения дают409, одновременные confirm создают одну запись. Повтор возвращает
  прежний результат с повторной проверкой доступа. Два preview не создают ветку.
- Поиск/QA по умолчанию исключают версии, у которых есть доступный ассистенту
  потомок. ACL применяется до этого выбора и до FTS5. Невидимая или secret-версия
  не меняет выдачу, предупреждения или статистику ранжирования. История проверяет
  права каждой редакции и скрывает ссылку на недоступного предшественника.
- Контекст встречи использует только явно прикреплённые редакции. Новая версия
  не подменяет материалы других встреч. Если прикреплены обе, для модели берётся
  актуальная. Если оставлена только старая, ответ предупреждает о доступной новой.
  Добавление новой редакции во время генерации не позволяет сохранить старую справку.
- В QA есть «Искать также в прошлых версиях» (`include_history=true`). Новый запрос
  использует актуальные редакции; сохранённый ответ остаётся историческим,
  показывает предупреждение о замене и перепроверяет права, цитаты и текст.
- `valid_until` и даты новых редакций — aware ISO8601; UI отображает Europe/Minsk; ISO ввод явно содержит смещение.
  Истёкший срок не удаляет файл, а даёт предупреждение, также при повторном чтении
  ответа. `Source.source_at` сохраняет договорённость: дата загрузки; дата создания
  документа отображается отдельно в метаданных.

## API

| Маршрут после `/api/meet/documents/{id}` | Действие |
|---|---|
| `POST /versions/preview` | multipart `file`, `authored_at?`, `valid_until?`; confirmation_id и preview |
| `POST /versions/confirm` | JSON confirmation_id, idempotency_key; новая редакция/повтор |
| `GET /versions` | только доступная история; до200 версий, повреждённая цепочка отклоняется |
| `GET /summary` | до5 точных выдержек со ссылками, `model:null`, честное insufficient_data |
| `GET /compare/{other_id}` | diff двух доступных редакций одной цепочки; «Было/Стало» со ссылками |

Отмена — общий `POST /api/meet/confirmations/{confirmation_id}/cancel`.
`/search` принимает query `include_history=true`, `/qa` — JSON bool того же имени.
Неподходящие фрагменты (инъекции, запрещённые запросы, размер вне12..1000) не
становятся выдержками/сравнением. `partial:true` явно помечает пропуски/лимиты.
Diff ограничен2000 исходных фрагментов,50 изменений и5 цитатами на каждую сторону.
Secret не используется в summary/diff; файл владельцу доступен отдельным путём.

## Данные и границы

Миграция13 добавляет таблицу временных файлов и индекс потомков. BLOB удаляется
при confirm/cancel, удалении просроченного confirmation через purge, а также при
следующем preview после истечения срока; максимум10 ожидающих файлов на человека,
каждый до5МБ. Фонового таймера удаления пока нет — остаётся задача E11.5.

«Кратко» — проверяемые выдержки, а не модельный смысловой пересказ. Diff сравнивает
подходящие фрагменты, не доказывает смысловую эквивалентность. Автоматического
поиска противоречий, извлечения обязательств, истории правок протокола, отдельного
редактора всех метаданных нет. При первичной загрузке нескольких файлов можно
выбрать отдел, конфиденциальность, тип и даты. Фильтры есть по названию, типу
и уровню доступа; файлы отправляются последовательно, это не атомарная загрузка.
Цепочка ограничена200 редакциями; прототип не рассчитан на многомиллионный архив.

Проверки: `tests/test_document_versions.py`, существующие migration/seed/QA tests,
`v2_http_smoke.py` (включая restart), браузерный путь в `v2_ui_check.py`.
Локальные модели не запускались; браузерный результат нового head проверяется CI.

## Опциональный выбор ключевых выдержек

`GET /documents/{id}/summary?semantic=true` либо
`MEETINGS_SEMANTIC_SUMMARY=1`: модель выбирает3–5 ID из первых30 подходящих
фрагментов (если фрагментов меньше, доступны все). Перед вызовом применяются
SQL/object ACL, secret exclusion, injection guards и PII masking. Выход —
только allowlisted уникальные ID; claim и цитата берутся из исходного текста.
После вызова повторно сверяются весь документ/ACL/фрагменты и предупреждения
об актуальности. Изменение →409, отзыв доступа →404, модель недоступна или
вернула неизвестный ID →503 без неподтверждённых claims.
Это выбор важности, не свободный пересказ; полноту/значимость оценивает хост.
Default по-прежнему не вызывает модель и показывает первые выдержки.

## Возможные противоречия и карта обязательств (E6.4/E15.2)

`GET /document-insights?meeting_id=…` — только чтение, без модели. В «Знания»
кнопка «Противоречия и обязательства». Для подготовки встречи тот же расчёт
ограничивается прикреплёнными документами и её репликами. Доступ, актуальная
редакция и secret проверяются до анализа. Источник с обнаруженной инъекцией
не анализируется. Устаревание помечается предупреждением.

Поддерживаемые ключи: номер PP-заказа, картон с толщиной в мм, ламинат, Kolbus;
атрибуты — явно указанная дата поставки и цена BYN. Один ключ «сущность + атрибут»
в разных доступных документах с разными значениями создаёт карточку «Возможное
противоречие» с двумя исходными цитатами. Это сигнал для человека: даты могут
описывать разные этапы или контексты. Правило не объявляет источник ошибочным.
История редакций по умолчанию не смешивается с актуальными документами.

Явные «обещает/обещаю/обязуется/подтверждает поставку» из документов и реплик
попадают в карту: кто (исходная подпись/говорящий), что (полная фраза), точная
дата или «требует уточнения», источник и связанные поручения. Условные,
отменённые, отрицательные обещания правила пропускают. Это ограниченная
грамматика, не полный semantic NLP и не юридическое определение обязательства.
Исполнение обещания не выводится автоматически из слов: показываются текущие
статусы вручную связанных задач, а не доказанное исполнение поставщиком.

Кнопка готовит редактируемую задачу ассистента. Пользователь выбирает встречу-
основание/исполнителя/срок и отдельно подтверждает. Basis document:F… или
utterance:U… фиксирует исходник; текст/метаданные/ACL/редакция/роль повторно
проверяются на confirm. Изменение источника →409, отозванный доступ →404/409,
без задачи. Задача остаётся ручным поручением, запись встречи не подделывается.

Лимиты: первые500доступных текущих фрагментов и500реплик,30конфликтов,
50обязательств; при превышении видна отметка partial. Привязка к источнику
целого фрагмента может объединять несколько обещаний: человек проверяет
соответствие задачи. Браузерный микрофон и реальные модели этим не проверяются.
