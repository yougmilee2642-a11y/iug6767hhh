# Расширенный обзор и контроль результата

В «Обзоре» раскройте «Сезонный радар, качество, ПВЗ и контроль результата».
Панель не вызывает модель и не создаёт поручений автоматически.

## Формулы и границы

По каждому доступному участку берутся три последние завершённые недели:
`M = mean(occupied_hours / available_hours × 100)`.
Исторический коэффициент `K = mean(декабрьская загрузка) / mean(загрузка остальных месяцев)`.
Шесть будущих недель: `M × K` для недели, середина которой попадает в декабрь,
иначе `M`. Дефицит: `max(прогноз − 100, 0)`. В синтетическом примере
`M=75`, `K=111/75=1.48`, декабрьский прогноз `111%`, дефицит `11%`.
Недостаток трёх недель, истории или нулевой знаменатель → нет прогноза;
старый снимок → предупреждение. Это сценарная арифметика, не обученная модель.
`demo/track3/seasonality.json` — отдельное синтетическое расширение seed;
зафиксированные v1/v2 корпуса и gold не меняются.

Радар качества показывает отдельные числа заказов Premium с браком,
обращений/звонков о браке, открытых решений и просроченных поручений по качеству.
Числа ограничены текущими правами; корреляция не доказывает причину.
ПВЗ: только явно заданный срок хранения в диапазоне `[сейчас, сейчас+2 дня]`.
Для логистики это отдельная минимальная проекция номера/срока/перевозчика;
она не открывает клиента и сумму ERP-заказа. Первые 100 записей помечены как частичная выдача.

Каждый расчёт содержит подписанный источник `insight`. При открытии и подтверждении
действия сервер заново читает данные и ACL; изменённое основание даёт 404/409.
Кнопки создают редактируемый проект встречи или поручения через общий preview/confirm.

## Недельный дайджест

Выберите конец семидневного периода → предпросмотр → подтвердить/отмена.
Учитываются доступные поручения, календарь, новые документы и KPI. Статусы задач
текущие; восстановление исторических состояний не заявляется. После подтверждения
создаётся личный локальный EML, без внешней отправки. Скачать может только автор,
после повторной проверки прав и содержимого. Изменения требуют нового предпросмотра.
Дайджесты удаляются по сроку chat_days; удаление пользователя удаляет их также.

## Проверка результата решения

Подтверждённое решение с проверенной цитатой → метрика отдела, цель и направление
`≤/≥`, срок 1–90 дней → preview/confirm. Сохраняется исходный снимок.
После срока worker требует новый снимок, созданный после настройки контроля и
не старше 48 часов. Иначе статус «ожидается свежий снимок».
Пример автотеста: загрузка `111% → 96%`, цель `≤100%` достигнута.
Это сравнение числовой цели, не доказательство причинного эффекта решения;
статус поручений не меняется. Видимость исходного/нового снимков проверяется повторно.
Удаление решения каскадно удаляет контроль; удаление пользователя удаляет его проверки.

API: `GET /advanced-overview`, `POST /briefing/weekly/{preview,confirm}`,
`GET /briefing/weekly/outbox`, `GET /briefing/weekly/outbox/{id}.eml`,
`GET /effect-checks`, `POST /effect-checks/{preview,confirm}` под `/api/meet`.
Проверки: `tests/test_track3_advanced_reports.py`, реальный HTTP
`scripts/track3/v2_http_smoke.py`, браузер `scripts/track3/v2_ui_check.py`.
Последний сценарий требует доступного Chromium; модели и внешние аккаунты не используются.
