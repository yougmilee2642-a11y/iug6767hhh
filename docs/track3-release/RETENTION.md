# Хранение и удаление тестовых данных

Политика для синтетического тестового выпуска. Это **операторский регламент**, не
автоматический TTL приложения. Производственные сроки необходимо установить
отдельно с владельцем данных; этот документ их не придумывает.

| Данные | Место / фактическое поведение | Срок тестового хранения / удаление |
|---|---|---|
| Оригиналы документов, fragments, ACL | content BLOB и таблицы meetings DB, отдельной upload-директории нет | До конца демо, максимум 7 дней; удалить тестовую БД и SQLite sidecars |
| Расшифровки, original_text, speaker map | utterances/meetings; original + edited сохраняются | Те же 7 дней; удаление строки в UI может быть soft delete, окончательная очистка — БД |
| Prep, протоколы, задачи, summary, confirmations | SQLite; подтверждённый результат и черновики хранятся | Те же 7 дней; не считать cancel удалением preview из хранения |
| Календарь, занятость и local_outbox | SQLite, реальной отправки писем нет | Те же 7 дней, удалить БД |
| QA-запросы | Модулю нужен текст в памяти; qa_answers хранит SHA-256 вопроса, question_masked пустой | Raw question не сохраняется этим модулем; hash/ответ/claims — 7 дней |
| Результаты QA и источники | qa_answers; при открытии повторная ACL и проверка целостности | 7 дней; удалить БД, источники в отчётах удалить отдельно |
| Feedback и аудит | SQLite; аудит содержит IDs/модель/коды, маскированные метаданные; контекст не логируется | 7 дней; удаление тестовой БД включает аудит, не отдельный selective purge |
| Секрет сессии / cookie | *.session.key или внешний MEETINGS_SECRET; signed cookie клиента | После демо удалить тестовый key, выйти из обеих учёток; внешний секрет оператор убирает отдельно |
| Cabinet test DB | соседняя *.cabinet.db с sidecars, только изолированный start.py | 7 дней, cleanup включает только зарегистрированные файлы |
| Аудио / голосовой профиль | В текстовом сценарии отсутствуют; голосовой runtime держит буферы/профили в памяти | Остановить процесс; отдельно проверить любые вручную сохранённые записи/логи браузера; микрофон здесь не проверялся |
| Live/HTTP/CI отчёты и screenshots | По явному output/артефактам CI; могут содержать цитаты synthetic corpus | Локальные 7 дней; CI artifact 7 дней (workflow); исходный отчёт не переписывать при review |
| Синтетические fixtures и gold | git demo/track3 и evaluation/track3 | Хранятся как часть исходников, реальных данных нет |
| Backup/синхронизация и gateway logs | Не создаются release-скриптами и не контролируются ими | Оператор удаляет все копии по конкретным путям в течение 7 дней; проверяет sync/host/Cloudflare-политику отдельно |

Перед cleanup остановить сервер: открытая SQLite/backup могут сохранить копию данных.
Dry-run по умолчанию показывает **только файлы**, не раскрывает содержимое. Требуются
абсолютный путь, marker, явный --confirm-delete. data/ защищена, рекурсивного удаления
и удаления произвольного каталога нет. Отчёты разрешены только явно заданными файлами
рядом с БД. Не запускайте VACUUM/удаление строк на рабочей БД ради smoke.

Удаление файла не обещает физическое стирание носителя, версий backup, облачной
синхронизации или host-логов. Для real данных использовать утверждённую процедуру
владельца устройства/backup. Остановка remote gateway или туннеля сама по себе
не удаляет внешние журналы. Логи терминала и history с токенами не коммитить.


Авторский voice MVP (#9) добавляет WAV request buffers в handlers transcribe/wake:
их release-маршруты не сохраняют в meetings DB, ответ помечен no-store. Wake не пишет
raw речь в audit; voice.ask хранит metadata, а вызванный им QA — обычный hash/result
по таблице выше. Поведение decoder/temp и вручную сохранённых аудио-файлов нужно
проверять отдельно в конкретном speech runtime: голосовые веса здесь не установлены.
Внешние Google Fonts request metadata контролируются провайдером ассетов, а не
cleanup тестовой БД; font-requests отчёт содержит только synthetic CI network URLs.


Опубликованные **синтетические** release-observations в docs/track3-release/reports
хранятся в git для воспроизводимости на срок жизни репозитория/его клонов, как fixtures
и gold. Это отдельный срок от7 дней для временных runtime-файлов и CI-артефактов.
Рабочие документы, реальные meeting reports, аудио и секреты в git не помещать.
Cleanup тестовой БД не удаляет git history, PR comments, клоны или внешние backup;
их удаление требует отдельной процедуры владельца хранилища. Никакой автоматической
очистки истории/main этими скриптами не выполняется.
