## Извлечение задач и QA v2

Нужны: чистая опубликованная ветка, Python 3.12 с
`requirements-track3-v2-test.txt`, заранее установленная Ollama-модель и
согласованное окно без параллельных тяжёлых запросов. Флаг ниже — подтверждение
оператором уже согласованного окна; агент не резервировал общую GPU и не
утверждает, что окно получено.

Модель `qwen2.5:7b` — значение по умолчанию, не обязательная загрузка стартового
текстового пути. Время скачивания, скорость, свободные RAM/VRAM и холодный старт
зависят от хоста. Точный digest/размер установленного варианта фиксирует отчёт;
без этого прогона размер/время для данного хоста здесь не измерены.

Настройки: `MEETINGS_MODEL`, `MEETINGS_CONTEXT` (8192 по умолчанию),
`MEETINGS_TIMEOUT` (300 s). Сетевой путь использует существующую проверку
`providers.ollama.endpoint()`: loopback по умолчанию; защищённый gateway только
с разрешением адреса/HTTPS/Bearer. Redirect и env-proxy отключены, cloud-модели
запрещены. Не добавлять токены/адреса с секретами в отчёты или Git.
Данные remote gateway обрабатываются на машине хоста; Cloudflare — ещё внешний
посредник. Это не полностью локальная обработка на компьютере пользователя.

PowerShell (из корня, выбрать **новый абсолютный** JSON-путь):

```powershell
$reportPath = Join-Path $env:TEMP ('photoprint-v2-live-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.json')
.\scripts\track3\live_eval.ps1 -PythonExecutable .\.venv\Scripts\python.exe -OutputPath $reportPath -ExclusiveGpuWindow
```

Linux/macOS:

```bash
python scripts/track3/evaluate.py --dataset photoprint-v2 --exclusive-gpu-window --output /absolute/new-live-v2.json
```

Оценщик сам создаёт и удаляет отдельную временную БД с синтетикой. Рабочая
`data/` не очищается. Существующий report не перезаписывается; checkpoint
записывается после каждой расшифровки/вопроса. Не прерывать процесс удалением
отчёта; Ctrl+C оставляет `interrupted`. Для новой попытки нужен новый путь.

В live-отчёте должны быть model/digest/Ollama version, commit/dirty, dataset/hash,
gold_commit, параметры, время и задержки, исходные ответы, источники и ошибки.
Порог: ≥5/6 строгих задач в **каждом** из 5 текстов, ≥80% суммарно, все 36
контролей; 0 нарушений прав и ложных действий; спорные формулировки — независимому
человеку. `pipeline_passed` — статус дублёра, не успешная live-оценка.

Для независимого пересмотра: формат из `EVALUATION.md`, затем
`python scripts/track3/score_report.py --report /absolute/original.json --review /absolute/human-review.json --output /absolute/new-reviewed.json`.
Оригинал остаётся неизменным; нельзя обходить подтверждение цитаты или менять gold.

## Голос и аудио (отдельно)

ASR, TTS, диаризация, микрофонный поток и реальные аудиофайлы
**не проверены живьём для v2**. Аналитика звонка реализована и проверена
на синтетических текстах/таймкодах; это не проверка распознавания. Контроль `call_defect`
использует уже готовый синтетический текст и проверяет извлечение задач.
Не записывать его как успешный тест распознавания или звонка целиком.
Готовые голосовые веса и проверка устройств нужны на хосте; их размер и время
установки для этого выпуска ещё не измерены. См. существующий голосовой runbook
в `MEETINGS.md`; старые «3 из 3» не являются новой проверкой v2.

## E7 · аудиоконвейер на хосте

Агент не запускал этот сценарий с моделями. Подготовьте синтетическую WAV-запись
с двумя согласившимися участниками, прочитавшими разные реплики из контрольного
звонка. Не используйте реальные клиентские данные. Установите существующий
локальный voice stack и веса по runbook; скрипт их не скачивает. Нужны ASR
GigaAM/T-one и sherpa segmentation/WeSpeaker; TTS и Ollama этим скриптом не вызываются.

```powershell
.venv\Scripts\python scripts\track3\live_audio_pipeline.py --audio C:\Temp\synthetic-two-speakers.wav --output C:\Temp\new-audio-report.json --allow-models --synthetic-with-consent --expected-speakers 2
```

CLI требует явные flags и новый абсолютный output. Он создаёт отдельную временную
синтетическую DB, загружает запись с consent, проверяет job/таймкоды/число говорящих
и preview/confirm импорта. Результат `pipeline_passed` подтверждает только путь
выполнения. Хост вручную сверяет исходную запись и каждую реплику; число говорящих
и наличие текста не доказывают качество ASR или правильность диаризации.
Если модель недоступна, ошибка503 содержит job; в обычном API исходный файл
сохраняется до retry/политики хранения. После перезапуска незавершённый job
помечается interrupted; повтор запускает человек. Прототип — один процесс API.

В браузере отдельно: согласие перед стартом, индикатор «все уведомлены»,
автоостановка после2 минут тишины, воспроизведение по таймкоду источника,
отказ чужого профиля, правильный показ удалённого по сроку оригинала. Микрофон
и TTS здесь не проверены агентом. RMS-порог тишины — технический, не VAD-оценка.

## E7 · фиксированный текстовый контроль звонков без моделей

```powershell
.venv-track3\Scripts\python scripts\track3\evaluate_calls.py --output C:\Temp\new-calls-control.json
```

Оригинальный `call_defect.txt` и его SHA из v2 сохранены. Отдельный
`call_defect_timed.txt` добавляет синтетический тест времени/перекрытий.
Ручные ожидаемые признаки и SHA обоих текстов: evaluation/track3/calls/.
Оценщик проверяет17 тем, цитатный чек-лист, триггеры, сигнал риска, тайминги,
чужой scope, повторconfirm и отсутствие скрытых задач. Это проверка правил,
не оценка настоящей модели и не доказательство фактического оттока клиента.

## E5 · голос ASR → чтение/черновик → TTS на хосте

Запишите синтетический WAV до4МБ, например «Фокус, поставь задачу Денису
проверить картон до пятницы» или «Фокус, брифинг». Только свои голоса с согласием.
Скрипт использует отдельную временную БД, не вызывает Ollama, прекращает работу
при неожиданной маршрутизации к знаниям. Он проверяет отсутствие скрытых
задач/встреч/отправок и записывает задержки. Для каждой команды новый отчёт.

```powershell
.venv\Scripts\python scripts\track3\live_voice_check.py --audio C:\Temp\synthetic-command.wav --output C:\Temp\new-voice-report.json --tts-output C:\Temp\new-focus-reply.wav --allow-models --synthetic-with-consent
```

Проверьте вручную распознанный текст, исполнителя/дату, произношение и скорость.
Если рядом слушатели, звук может быть запрещён политикой доступа: это ожидаемо.
На телефоне отдельно проверьте HTTPS, разрешение микрофона и push-to-talk;
файловый скрипт не доказывает работу устройства/браузера.

## E6/E7/E10 · настоящая модель выбора фрагментов/тем/инструмента

```powershell
.venv\Scripts\python scripts\track3\live_read_tools.py --output C:\Temp\new-read-tools-report.json --allow-models
```

Только синтетические данные во временной БД. Отчёт фиксирует установленную
модель/digest, ответы и задержки сводки, read-router и17тем звонка; без реальных
CRM/почты. Подготовка тестового звонка — явный ручной preview/confirm внутри
сценария. Проверяется отсутствие дополнительных бизнес-записей от модели.
`pipeline_passed` не доказывает смысловую точность: хост отдельно оценивает
важность3–5 выдержек, правильность выбранного инструмента и тем по цитатам.
