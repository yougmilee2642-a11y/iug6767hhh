# Календарь: локальный mock, ICS и файлы приглашений

В «Встречи» раскрыть **Мой календарь · ICS и приглашения**. Стили существующие.
Все действия работают без модели, SMTP и внешних аккаунтов.

- **Скачать мой календарь .ics**: только подтверждённые события, где пользователь
  организатор/участник. Название включается при текущем доступе к встрече. Прямой
  запрос чужого события даёт 404. UTC `DTSTART/DTEND` с `Z`; клиент показывает
  местное время. `X-WR-TIMEZONE` — подсказка Europe/Minsk, не замена UTC.
- **Создать ссылку подписки**: после экранного подтверждения выдаётся signed bearer
  на 90 дней. Показывает только время/«Занято», без названий/участников. БД хранит
  SHA256 токена. Новая ссылка отзывает прежнюю; кнопка отзыва прекращает будущие
  чтения. Проверяются active/роль на каждом чтении. Копия уже скачанного календаря
  у стороннего клиента не удаляется. Подключение Google/Outlook передаёт туда время
  занятости; это самостоятельный выбор пользователя, в демо не выполняется.
- **Предпросмотр импорта**: файл UTF-8 до 1 МБ/500 событий. Показывает интервалы;
  до confirm `calendar_busy` не меняется. Confirm атомарно заменяет только свой
  `source=ics-upload`; ручная занятость и встречи Фокуса сохраняются. Отмена,
  повтор, два параллельных confirm и конкурирующие snapshots проверены тестами.
  Исходные названия/описания/участники/вложения не хранятся и не попадают в модель.
- **Скачать приглашение .eml**: только организатор/адресат, только существующая
  подтверждённая запись outbox. MIME-письмо с ICS, адреса `user-N@demo.invalid`.
  Файл формируется при скачивании с повторной проверкой прав адресата и зрителя.
  Письмо не отправляется. Названия в ранее сохранённой очереди также перепроверяются.

API относительно `/api/meet/calendar`:

| Метод | Путь | Результат |
|---|---|---|
| GET | `/export.ics?event_id=N` | Одно событие; без event_id — мой календарь |
| POST / GET | `/subscriptions` | Выдать ссылку / метаданные моих ссылок без токенов |
| DELETE | `/subscriptions/{id}` | Отозвать свою ссылку, повтор безопасен |
| GET | `/feed/{token}.ics` | Только чтение busy-only без cookie; отозванный/истёкший → 404 |
| POST | `/import/preview` | multipart `file`, `timezone` для floating/all-day |
| POST | `/import/confirm` | `confirmation_id`, `idempotency_key` |
| GET | `/outbox/{id}/download.eml` | MIME-приглашение с ICS |

Общая отмена: `POST /api/meet/confirmations/{confirmation_id}/cancel`.
Admin/auditor не имеют `calendar.view`. Отказы/экспорты/import/подписки журналируются
без текстов событий и bearer-токена; фильтр access log редактирует путь feed.
Reverse proxy должен отдельно скрывать `/api/meet/calendar/feed/*` в своих логах.

Поддерживаемый импорт: `VEVENT` с UID/DTSTART/DTEND, UTC или IANA TZID; floating
интерпретируется в явно выбранной зоне. All-day DATE — полуоткрытый интервал,
без DTEND — один день. Неоднозначное/несуществующее DST-время отклоняется.
Отменённые/прозрачные события не блокируют время. RRULE/RDATE/EXDATE/RECURRENCE-ID,
DURATION и custom VTIMEZONE отклоняются, чтобы не создавать ложное свободное
время. Нужно экспортировать отдельные события с DTEND и UTC/IANA.

Основа формата сверена 12.11.2026 по [RFC Editor, RFC 5545](https://www.rfc-editor.org/rfc/rfc5545.html)
и [IETF Datatracker](https://datatracker.ietf.org/doc/html/rfc5545): CRLF, TEXT
escaping, folding по 75 octets, UTC instants. Это ограниченный импорт, не полная
реализация RFC и не живая проверка Outlook/Google/Яндекс.

Bitrix24/Google и локальные серии описаны ниже. EML доступен скачиванием
и материализуется в локальном outbox воркером; SMTP выключен по умолчанию; отдельное согласие/флаги/транспортные проверки описаны в [DELIVERY.md](DELIVERY.md). Падение файловой системы не может
откатить календарь или привести к повторной внешней отправке: её здесь нет.

## Подбор с рабочим графиком

В подготовке включён флажок «Учитывать смены, перерывы и буфер 10 минут».
API `/slots` и `/preview` принимают `smart: true`, `participant_ids` (обязательные)
и `optional_participant_ids`. Организатор всегда обязательный. Выдача — три
слота с наименьшим числом конфликтов у необязательных, затем ближайшие по времени;
каждый содержит объяснение и `optional_busy_count`. В UI необязательность можно
указать только выбранному участнику. Без smart сохраняется прежний алгоритм.

Для каждого участника учитываются его IANA-пояс, явные work_shifts и перерывы,
наличие занятости с буфером10 минут с обеих сторон, HR-отсутствия по табельному
коду. Причины отсутствий/названия событий/строки HR/графики наружу не выдаются:
это отдельная производная free-busy проекция, а не доступ к документам HR.
Пользователи inactive/admin/auditor исключены из календарных участников.

Если графика никогда не было — явно предупреждённый fallback: будни09:00–18:00,
планёрка09:00–09:15, обед13:00–14:00 в зоне участника. Явные смены имеют приоритет
и используют свои перерывы. Для пользователя со сменным графиком отсутствие
смен в выбранном периоде означает отсутствие доступного времени, не офисный
fallback. Внешний free/busy опрашивается только при явно включённом провайдере;
по умолчанию используется локальный mock.

График старше24 часов → предупреждение. `MOCK_CALENDAR_FAULT=down|stale` проверяет
недоступность/устаревание; down →503 calendar_unavailable без изменения встречи.
При confirm проверяются график, занятость, active/пояс и новые предупреждения.
Изменившееся время →409/422, новый warning →409 stale. Отменённый preview не
создаёт события; повтор подтверждения возвращает прежнее. Успешный подбор и
ошибки источника пишутся в аудит без содержимого чужих событий/HR.

## Серии и настраиваемые напоминания (E4.4–4.5)

`POST /calendar/series/preview` принимает title/start_at/timezone/frequency
(daily, weekdays, weekly), count2..30, duration_minutes15..480, participant_ids,
smart (по умолчанию true). Все даты вычисляются в IANA-зоне; неоднозначный
переход часов отклоняется. Preview показывает каждую дату, участников и
предупреждения. Confirm повторно проверяет текущую роль, отдел, справочник,
занятость/смены и создаёт отдельную встречу и локальное событие для каждой даты.
Повтор confirm не создаёт дубль; отмена/изменение данных не создают серию.

Серия конечная, без автоматического продления. Каждая встреча имеет series_id
и собственные расшифровку/протокол. Незакрытые задачи других доступных встреч
серии появляются в личном контексте следующей повестки, с источником;
не копируются автоматически другим участникам. Списки по текущему ACL,
secret/admin/auditor не получают содержимое серии. Внешние провайдеры требуют
отдельного preview/confirm каждой встречи: массовая внешняя серия отключена.
Экспорт ICS содержит отдельные VEVENT; импорт RRULE по-прежнему отклоняется.

Во «Встречи → Мой календарь → Повторяющиеся встречи» доступны форма и список.
В «Уведомления» настройка reminder_minutes:0..1440 (0 выключает), default15;
изменение через preview/confirm. Tick создаёт одно уведомление с переходом
к повестке и никогда не меняет задачи/встречи. Приглашения — local EML;
напоминания во внешних каналах требуют opt-in.

## Google Calendar (P2, по умолчанию отключён)

`MEETINGS_CALENDAR_PROVIDER=google`, отдельный `MEETINGS_GOOGLE_ENABLED=1`.
Адаптер переиспользует integrations/providers.GoogleCalendar: HTTPS Google,
без proxy/redirect, ограниченный timeout и те же network_allowed gates
(CALLWISE_LOCAL_ONLY, CALLWISE_CLOUD_INTEGRATIONS_ENABLED, isolated DB).
Сама настройка флага не обходит глобальный запрет внешних интеграций.
`MEETINGS_GOOGLE_CREDENTIALS_ENV` — имя переменной пути к согласованному
service-account JSON (default CALLWISE_GOOGLE_CREDENTIALS). Файл/ключи в Git
не входят. Нужны установленные host-only credentials dependencies и доступ
сервисного аккаунта к календарям; агент ничего не подключал.

Сопоставления local user_id → calendar_id задаёт владелец через JSON
`MEETINGS_GOOGLE_CALENDAR_MAP` либо user_external_ids(connector=google).
Без нужного/уникального сопоставления подбор/confirm закрываются ошибкой.
В API бизнес-пользователей внешние calendar_id и пути credentials не выдаются.
Proof фиксирует хеш маппинга/назначения; изменение после preview требует нового.

FreeBusy проверяется до подтверждения. Durable outbox сохраняет sending до
HTTP. Событие получает детерминированный ID/маркер; перед insert проверяется
существующая запись. Таймаут → uncertain, без автоматического повтора.
В Google пишется только частная блокировка организатора: общее название,
время и служебный маркер. Названия встреч, документы, почты участников и
список гостей не отправляются. Участники получают локальное EML/ICS и сами
добавляют его в календарь. Это ограниченный адаптер, не полная синхронизация
всех личных календарей/Google invitations. sendUpdates=none применяется вместе
с отсутствием attendees; Google предупреждает об ограничениях доставки/
синхронизации этого режима. Отмена/get доступны на уровне адаптера только
для собственных подтверждённых external_ref, отдельного UI отмены пока нет.

Методы сверены12.11.2026 по первичным источникам:
[freeBusy.query](https://developers.google.com/workspace/calendar/api/v3/reference/freebusy/query),
[events.insert](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert),
[API reference](https://developers.google.com/workspace/calendar/api/v3/reference).
Проверки только httpx.MockTransport с синтетическим bearer. Реальных аккаунтов,
календарей и отправки не было. Тесты: test_track3_planning.py и общие calendar/
cloud_integrations tests. Ранее написанные отметки «серии/Google ещё нет»
описывают прошлый срез и заменяются этим разделом.
