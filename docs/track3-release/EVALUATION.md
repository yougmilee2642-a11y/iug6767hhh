# Протокол оценки Фотопринт v1

Эталон составлен вместе с синтетическими сценариями до вызовов проверяемой LLM; независимая человеческая проверка ещё не проведена. Исходный локальный коммит
`9d1c2dc`. 24 TXT-документа разных **деловых типов** (реестр, письмо, акт, план,
журнал, бриф, регламент), 3 расшифровки, 18 активных явных поручений и 16 QA-вопросов.
Новые файлы имеют один технический формат TXT; DOCX/PDF покрываются существующей
«Орбитой» и её тестами. Никакой проверки OCR, ASR или качества на реальных встречах
этот corpus не заменяет. Dates/ACL/исторические задачи/календарь/KPI — manifest.json.

## Метрики

- **Recall задач** = корректные задачи / все 18 явно сформулированных активных
  задач gold, по 6 на расшифровку. Корректность включает действие, точную опору,
  исполнителя и срок (включая честное unknown). Ошибка владельца/срока снижает recall.
  Если один запрос упал, его gold остаётся в общем знаменателе.
- **Precision** = корректные задачи / все предсказанные task; отдельно action_recall
  и action_precision без требования правильности полей. Дубликат сверх одного
  соответствия — лишний prediction. При нуле predictions precision=0, recall=0.
- **Source support**: доля predictions с точной цитатой, которую оценщик сам находит
  в stored utterance. Одного флага verified от модели/сервера недостаточно.
- Сопоставление взаимно однозначное (maximum bipartite matching). Обязательны
  совпадение U-id соответствующей эталонной реплики и исходная точная цитата;
  автоматическая формулировка допускается только из frozen alternatives.
  Перефразирование вне списка — unresolved, результат не повышается автоматически.
- Для спорного случая независимый человек проверяет действие и цитату; та же модель
  не используется судьёй. Повторный скоринг сохраняет исходный raw report.
- QA проверяет status, ожидаемые filenames и фрагменты цитат, resolver источников,
  даты, отсутствие запрещённых данных. Отказы — явно unknown year/private/injection.
- Latency — wall clock всего draft handler (включая проверку и summary), отдельно
  QA. Cold/warm влияние и конкуренция GPU должны быть описаны оператором; текущая
  среда таких измерений не содержит.

Цель: ≥80% recall **каждой** расшифровки и в целом; с шестью gold это минимум
5/6 для каждой. Дополнительно все 16 QA-кейсов должны пройти, ручные вопросы
разрешены. Даже достижение recall не закрывает независимую установку/UI/лицензии.

## Независимый пересмотр

На основании raw report независимый человек создаёт JSON:

```json
{"predictions_sha256":"скопировать из исходного отчёта","transcripts":{"delay":[{"prediction_index":0,"gold_id":"delay-1","verdict":"match","reviewer_kind":"independent_human","reviewer":"имя проверяющего","reason":"действие эквивалентно, цитата подтверждает"}]}}
```

Или verdict=false_positive. Нельзя обходить проверку точной цитаты. Индексы относятся
только к kind=task predictions в порядке отчёта. Затем:

```bash
python scripts/track3/score_report.py --report /tmp/track3-live.json --review /tmp/review.json --output /tmp/track3-reviewed.json
```

Скрипт сверяет corpus и hash predictions, запрещает перезаписывать исходный report.
Не оценивает отсутствующий прогон. Правки frozen gold требуют новой версии набора
до следующей оценки, их нельзя представлять результатом текущей.

Термин human-authored в ранних именах коммитов/HTTP report означает сценарную

## История усиления: scorer_version 2

Замороженные документы, gold и expected не менялись. Исправлены три воспроизведённых
ложных успеха: текст «Не проверить поставку…» содержал нужные ключевые слова;
три копии delay засчитывались за три контроля; QA могла содержать верную цитату
рядом с неподтверждённым утверждением. Новые регрессии проверяют именно эти случаи.

Автоматический task match теперь требует **полного** совпадения нормализованной
формулировки с заранее зафиксированным text/alternatives, корректной цитаты и
неизменённой исходной реплики. Добавленные действия, отрицания и вопросы уходят
на независимый review. Неизвестный/противоречащий статус поля не считается
правильным владельцем/сроком. Ручной review не обходит проверку источника;
повторные/несуществующие prediction_index отклоняются.

Успех требует по одному delay/planning/control, правильных corpus SHA и знаменателей,
всех 16 **различных исходных** QA-кейсов, наблюдённых версии/digest модели и
подтверждённого GPU-окна. Копии контроля/вопроса не повышают общий recall.
QA независимо проверяет соответствие text ↔ quote ↔ полное предложение источника,
answer ↔ claims, список sources и дату загрузки. Отрезать отрицание внутри
предложения или добавить свободный ответ с выдуманным фактом нельзя.

На этом этапе отчёты имели schema_version=2/scorer_version=2. Текущая версия — 3. Старые первичные отчёты остаются
неизменными; offline scorer не смешивает разные версии оценщика. `--review-file`
удалён из live-команды: пересмотр существующего отчёта выполняется **только**
score_report.py и никогда не запускает новую модель.

Выходной путь должен быть новым абсолютным .json, без symlinks. Существующие
отчёты и файл review не перезаписываются. Путь резервируется до инференса;
после каждого контроля и QA сохраняется checkpoint, при Ctrl+C — interrupted
с уже полученными результатами. Незавершённый прогон не превращается в passed.
Отчёт фиксирует фактические predict/schema hash/latency/исход каждого вызова модели,
не записывая промпты и токены. Инференс не начинается на dirty checkout или без
подтверждения согласованного GPU-окна.


## Scorer v3: независимые границы цитат

Новые отчёты имеют schema_version=2/scorer_version=3. Перенос строки не отделяет
условие/отрицание от утверждения; сокращения валюты и инициалы не завершают цитату.
Проверка не импортирует product excerpt helper. Старые отчёты v2 сохраняются без
переименования; offline scorer явно отклоняет несовместимую версию. Frozen gold и
expected неизменны. Это исправление оценщика, не новый результат модели.
