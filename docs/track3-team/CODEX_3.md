## Что сделать параллельно с остальными

1. Первый коммит — этот пакет заданий, чтобы все могли получить одинаковые инструкции. Зафиксировать SHA базы, список веток, команды проверки. Не добавлять в коммит пользовательские файлы. Ты единственный редактор общего CONTRACT после согласования.
2. Устранить реальное несоответствие LLM: `MeetingLLM` должен поддержать разрешённый защищённый шлюз через существующую `providers.ollama.endpoint()` без копирования ослабленной проверки адресов. Передавать Bearer, не следовать redirect, отключить env-proxy, блокировать cloud-модели и незашифрованный публичный HTTP. Сохранить loopback по умолчанию, schema/think/лимиты и обработку timeout. Отдельно документировать, что remote gateway обрабатывает данные на машине хоста, а cloudflare-туннель добавляет внешнего посредника. Не называть такой режим полностью локальным на машине пользователя.
3. Добавить **≥20 синтетических документов и 3 расшифровки** по «Фотопринт»: задержка фотокниг, производственное планирование, итоги/контроль поручений. Разные даты, типы документов и ACL; открытые/просроченные/завершённые задачи, тестовый календарь, числители/знаменатели KPI. Формат согласовать с Codex 2/Claude. Существующий набор «Орбита» и тесты не ломать: новый dataset в demo/track3, отдельный seed подкомандой/скриптом. Повторный seed без reset не создаёт дублей.
4. Данные для оценки: эталонные задачи с обязательными цитатами/владельцем/сроком и альтернативными формулировками; минимум 15 контрольных вопросов с ожидаемыми источниками и отказами; случаи инъекций, отмены, неизвестного срока и закрытых данных. Эталон фиксируется до оценки. Не подгонять expected под результат модели.
5. Оценщик настоящей модели: recall задач = найденные корректные явно сформулированные задачи / все такие задачи в эталоне; цель ≥80% на каждой из трёх контрольных расшифровок и общий результат. Показывать precision, ложные задачи, ошибки исполнителя/срока, опору на источник и задержку. Один эталон не матчится нескольким предсказаниям, смысловой матч подтверждается цитатой и при сомнении ручной проверкой; та же модель не единственный судья. Отчёт хранит model/version, commit, параметры, время, датасет и наблюдаемые результаты. Если реальный LLM недоступен — явно «не проверено», не успешный результат.
6. Минимальный запуск для трека 3 без обязательной загрузки всех голосовых весов: текстовый путь из ТЗ должен работать отдельно, если технически возможно в существующем приложении. Если app при старте требует голосовые пакеты, передай конкретный запрос владельцу, не патчи app.py самовольно. Инструкция: env, seed, start, две учётки, shutdown, хранение и удаление. Проверить установку другим участником; измерить время. Если модели надо скачать заранее, честно указать это и размеры/условия, не обещать 15 минут без измерения.
7. Безопасная очистка только заданной тестовой БД и артефактов: dry-run по умолчанию, явный путь и флаг подтверждения, проверка абсолютных путей, запрет рабочего default без отдельного явного согласия. Никогда не стирать текущую data/ для smoke. Все тесты используют временную БД. Политика хранит перечень данных/сроки и описывает удаление запросов, файлов, транскриптов, результатов, аудита и резервных копий.
8. Перечень библиотек, моделей и заимствований с версиями/commit и лицензиями по фактическим источникам. Веса и код проверяются отдельно. Новые технологии из ресерча не включать в список используемых, если их нет в продукте. Ограничения лицензии не угадывать.
9. CI на чистой среде без GPU/секретов: базовые meetings/voice-routing/gateway проверки и новые unit/integration tests, UI tests по фактической команде Codex 1, syntax/diff checks. Live-model оценка — отдельный явно запускаемый локальный шаг. Добавить отчёт соответствия ТЗ, архитектуру/потоки, актуальное API, сценарий 5–7 минут, структуру до 10 слайдов и честные ограничения.

Согласовать одно окно доступа к общей GPU для трёх расшифровок: не смешивать замеры с параллельными тяжёлыми запросами коллег. Не выдавать существующие «3 из 3» в MEETINGS.md за новые измерения.
