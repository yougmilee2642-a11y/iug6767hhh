## Знания

Сделай `POST /api/meet/qa` согласно контракту. Поиск → допустимые фрагменты → ограниченный контекст → MeetingLLM → сверка ссылок/цитат → ответ. Начни с существующего разбора документов и ранжирования; не мигрируй проект в PostgreSQL/pgvector/Haystack ради ресерча.

Каждое фактическое утверждение имеет проверенное основание и дату источника. Одного существования цитаты недостаточно для доказательства произвольного вывода: ограничь claims утверждениями, поддерживаемыми цитатой, а при сомнении покажи фрагмент/отказ. Указанные моделью чужие F-id, фальшивые цитаты и дополнительные утверждения отбрасываются. Нет релевантного материала — `insufficient_data`. Инъекция в документе не меняет инструкции и ничего не запускает.

В режиме встречи проверяется и встреча, и каждый приложенный документ; в глобальном режиме — все доступные документы. ACL отбирается до модели, затем повторно перед сохранением/выдачей результата при длительной генерации. Сохранённый ответ нельзя повторно выдать после отзыва доступа. Не делай глобальный кэш без ключа пользователя и прав.

Логи: используемые источники, model, request ID и результат через общий audit; полный контекст не логировать. Ошибки модели — понятный 503, никакого тайного fallback. Сразу согласуй с Claude минимальные таблицы для answer ID и доступа; с Codex 3 — формат контрольных вопросов.

## Управленческий обзор

Сделай `GET /api/meet/overview` и защищённое открытие metric/task-источников. Открытые/просроченные задачи — из реального реестра. Производственные KPI — из синтетической витрины, которую загрузит Codex 3. Сразу передай ему точный формат fixtures, Claude — таблицы и индексы. Миграции выполняет только Claude.

Минимум формул: открытые = задачи со статусом не `done`; просроченные = открытые с распознанной due < текущей датой Europe/Minsk; заказы в срок = on_time/completed_orders×100; брак = defective_units/produced_units×100; загрузка = occupied_capacity/available_capacity×100. Существующие статусы `open|in_progress|done` сохраняются. При нулевом знаменателе null. Для каждой формулы объяснить единицу, период и источник.

Фильтруй ACL до агрегации, включая суммы и счётчики; директор и читатель могут получить разные метрики. Не выдавай перечень скрытых подразделений. Дата актуальности — timestamp исходной витрины, отдельно от generated_at. Нет витрины — пустое состояние и warning, не придуманный KPI. Сводку можно собрать кодом из рассчитанных данных, модель здесь не обязательна.

## Приёмка

Тесты QA: существующий ответ; отсутствие оснований; недоступный документ не попал в вызов LLM; подставной fragment ID; prompt injection; отзыв ACL; malformed/timeout модели; дата и открытие источника. Тесты overview: известная формула, нулевой знаменатель, просрочка на границе Минска, завершённые исключены, чужие данные исключены до расчёта, отказ при прямом доступе к источнику, пустая и старая витрина.

Двойники модели нужны для воспроизводимых тестов; дополнительно передай Codex 3 реальные контрольные вопросы для запуска на Ollama. Не объявляй double-тест доказательством качества модели. Проверь регистрацию после интеграции с Claude.

Handoff: SHA, список новых маршрутов, JSON примеры всех состояний, схема fixture, таблицы/миграции-заявки, тестовые команды и результаты, известные пределы поиска. Сначала поставь рабочий QA, затем обзор; не задерживай оба сценария ради продвинутого semantic search.
