## 0. Как работать с этим документом

### 0.1. Роль агента
Ты — единственный исполнитель (full-stack Python/JS) для трека 3. Твоя задача — довести CallWise «Фокус» (раздел `/meetings`) до сильного, проверяемого прототипа **AI-ассистента руководителя ООО «Фотопринт»**, затем провести самоаудит решения по чек-листу (раздел 9) и влить результат в GitHub (раздел 10).

### 0.2. Жёсткие ограничения
1. **Дизайн не делать.** Никаких новых цветов, шрифтов, иллюстраций, анимаций, переработки вёрстки. Разрешено: функциональные кнопки, формы, таблицы, списки, модальные окна предпросмотра в **существующем** стиле (`static/meetings.css`, классы, которые уже есть). Новые экраны — «базовые наброски»: заголовок + таблица/список + кнопки. Если без CSS не обойтись — минимум, только layout (grid/flex), без визуальной стилистики. Помечай такие места комментарием `/* TODO(design) */`.
2. **Локальную модель не запускать и не тестировать.** Ollama (`qwen2.5:7b`), ASR (T-one/GigaAM/Whisper), TTS (Silero), диаризация (`models/speaker/*.onnx`) — недоступны агенту. Всё, что зависит от модели, тестируется через **дублёры** (scripted model double — см. `tests/test_meetings.py`, `tests/evaluation_doubles.py`). Для живой проверки агент **пишет готовые скрипты** `scripts/track3/live_*.py` с ожидаемым результатом и инструкцией в `docs/track3-release/LIVE_CHECKS.md` — их запустит хост (Лёша). Агент не утверждает, что живая проверка пройдена.
3. **Всё остальное агент проверяет сам:** pytest целиком, JS-тесты (`node --test` для `static/**/tests`, `*.cjs`), HTTP-smoke через uvicorn + httpx, браузерный smoke (`tests/ui_track3/*`, если Playwright/браузер доступен; иначе — HTTP-smoke и явная пометка), чистая установка в новую папку по README, миграции на существующей БД и на пустой, повторная загрузка seed.
4. **Никаких реальных внешних аккаунтов и данных.** Bitrix24, Google, Telegram, SMTP — только транспортные дублёры и mock-провайдеры. Реальные ФИО/телефоны клиентов запрещены (ОТ-03). Секреты не коммитить; `.env`, `secrets/`, `models/`, `data/*.db` — вне git.
5. **AI предлагает — человек подтверждает.** Ни одна запись во внешнюю систему, письмо, приглашение, задача, изменение документа не выполняется без preview → confirm (AI-03). Голос и чат могут только создавать **черновик/предпросмотр**.
6. **Не трогать** незакоммиченный `start-gateway.ps1` (локальная правка хоста). Не включать его в коммиты. Запрещены `git add .`, `git reset --hard`, `git clean -fd`, force-push, массовое переформатирование.
7. Язык интерфейса и сообщений об ошибках — русский. Даты — aware ISO 8601, отображение Europe/Minsk; деньги — с валютой `BYN` (ОТ-07).

- **P1** — сильно повышает оценку («решение бизнес-задачи 25%», «данные и интеграции 15%», «безопасность 15%»).

## 3. Текущее состояние CallWise (аудит на 11.11.2026)

Стек: FastAPI + SQLite (`data/meetings.db`) + vanilla HTML/JS, Ollama `qwen2.5:7b` (только loopback или авторизованный шлюз), ASR T-one/GigaAM, TTS Silero, диаризационные ONNX-модели лежат в `models/speaker/` (используются только для «gating» в звонках, не для встреч).

### 3.1. Уже есть (не переписывать)
- `/meetings` с вкладками Обзор / Встречи / Знания / Задачи; встреча: 1 Подготовка · 2 Материалы · 3 Протокол · 4 Задачи.
- Документы TXT/DOCX/текстовый PDF → фрагменты; ACL на встречу/документ (`can_read_meeting`/`can_read_document`), 404 для чужого.
- Подготовка (`/prepare`) со справкой и цитатами; редактирование стенограммы с сохранением оригинала; маппинг говорящих.
- Извлечение протокола (`meetings/extract.py`): `decision|proposal|task|open_question|risk`, outcome `accepted|rejected|discussed|none`, проверка цитат по хранилищу, проверка имени/даты по цитируемым строкам, второй проход по «надо/нужно».
- Подтверждение задач без дублей (`tasks.protocol_item_id UNIQUE`), preview/confirm/cancel (`meetings/confirmations.py`), следующая повестка.
- Роли `reader` / `manager` с capability-списком (`meetings/auth.py`), аудит отказов.
- Календарь-мок: участники, слоты, preview/confirm/cancel, events, outbox (`meetings/calendar/`).
- QA по знаниям с claims/sources (`meetings/knowledge/`), управленческий обзор `/overview` + resolver источников (`meetings/management/`).
- Обратная связь (`meetings/feedback.py`).
- Голосовой «Фокус» (`meetings/voice.py`, `static/meetings/voice.js`): push-to-talk, wake-фраза «Привет/Окей, Фокус», маршрутизация regex → knowledge/overview/action-refusal, режим «не озвучивать» с проверкой прав всех слушателей.
- Вне `/meetings`: адаптеры Google Calendar + Bitrix24 (сделки) для booking-агента (`integrations/`), Telegram-бот, телефонный голосовой агент, dual ASR.

### E2. Полномочия сотрудников разного уровня — P0

Цель: ОТ-02 и AI-02 в сильной форме: директор ≠ руководитель отдела ≠ сотрудник ≠ подрядчик ≠ аудитор, проверка **на сервере**, включая контекст модели, голос, поиск, обзор и экспорт.

**E2.1 Модель доступа (RBAC + атрибуты).**
- Уровни конфиденциальности документа/встречи/метрики: `public` (вся компания) · `internal` (сотрудники, не подрядчики) · `department` (свой отдел + директор) · `confidential` (явный список + директор) · `secret` (только явный список; **никогда** не уходит в модель, даже директору — только открытие файла владельцем; зарплаты, ПДн, договоры).
- Правило: доступ = (ACL объекта: owner/участник/share) **ИЛИ** (атрибутное правило по уровню и отделу), **И** capability роли на действие. Capability **никогда** не открывает чужой объект (сохранить существующий принцип).

| meetings.read / qa.ask / overview.read (в своём scope) | все | свой отдел + приглашён | свой отдел | приглашён | приглашён | — | — |
| overview.company (все отделы) | ✓ | — | — | — | — | — | — |
| meetings.create / edit / share | ✓ | ✓ | ✓ | — | — | — | — |
| transcript.edit / protocol.edit | ✓ | ✓ | ✓ | своя встреча | — | — | — |
| protocol.confirm / tasks.change | ✓ | ✓ | ✓ (без чужих отделов) | только статус своих задач | — | — | — |
| calendar.invite | ✓ | ✓ | ✓ | — | — | — | — |
| crm.write (экспорт в Битрикс24) | ✓ | ✓ | — | — | — | — | — |
| documents.upload / share | ✓ | ✓ | ✓ | ✓ (department) | ✓ (только свои) | — | — |
| calls.analyze / calls.read | ✓ | SUP/SALES heads | SUP lead | свои звонки | — | — | — |
| audit.read | ✓ | свой отдел | — | — | — | — | ✓ все |

- Admin **не видит содержимое** документов и встреч (разделение обязанностей) — только пользователей, интеграции, хранение. Auditor видит журнал, но не содержимое.

**E3.1 Контракт.** `meetings/connectors/contracts.py`:
```
class CRMConnector(Protocol):
    name: str
    def get_employee(self, external_id|email) -> Employee | None
    def list_departments(self) -> list[Department]
    def get_customer(self, customer_id) -> Customer | None          # обезличенно

    def find_interactions(self, order_no|customer_id) -> list[Interaction]  # обращения поддержки

```
Ошибки — существующий стиль `IntegrationError(code)`: `disabled|config|unavailable|conflict|uncertain|forbidden`. Каждое значение несёт `source_id` и `fetched_at` (для «данные устарели»).
