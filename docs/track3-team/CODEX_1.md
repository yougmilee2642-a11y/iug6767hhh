# Задание Codex 1 — единый интерфейс руководителя

Сначала прочитай `docs/track3-team/README.md` и `CONTRACT.md`. База `cb2614b86f3b83636e670c83a0afb8f4c9d6c3c3`, ветка `codex/track3-ui`. Реализуй и проверь весь пользовательский путь трека 3 в `/meetings`. Отдельный clone/worktree. Пушь свою ветку, открой PR; не пушь в main.

## Только твои пути

`static/meetings.html`, `static/meetings.js`, `static/meetings.css`; новые `static/meetings/` (модули при необходимости); новые `tests/ui_track3/`; `docs/track3-handoffs/codex1.md`. Общие `style.css`, `product.css`, кабинет, ASR, app.py и серверные meetings-файлы не редактировать. Стиль изолировать под meetings-page. Новые зависимости запрашивать у Codex 3.

## Что сделать

1. Сохранить нынешний сценарий, голосовой ввод и панель цитат. Добавить понятные разделы «Обзор», «Встречи», «Знания», «Задачи», без переделки старого продукта и без новой SPA-платформы.
2. Встреча: подготовка с открытыми задачами, редактируемые тема/участники, подбор свободного времени. Предпросмотр явно показывает дату, зону, участников и тестовые приглашения; только подтверждение вызывает calendar confirm. Отмена не выполняет запись. При 409 предложить обновить слоты, сохранить ввод.
3. Протокол: summary, решения, предложения с исходом, вопросы, риски, поручения. Цитата открывает настоящую реплику/фрагмент; видна дата источника. Неизвестные исполнитель/срок заметны; редактирование перед сохранением. Показывать итоговый список выбранных задач до подтверждения.
4. Знания: вопрос, ответ по проверенным claims, кликабельные источники с датой, понятное «оснований не найдено», глобальный и контекст встречи. Серверный ответ не вставлять через innerHTML. Feedback «полезно/ошибка» и комментарий с явной отправкой.
5. Обзор: KPI, актуальность, источник и формула; просроченные задачи ведут в исходную встречу/задачу. Null и устаревшие данные показывать честно. Значения получать с API, не рисовать константы под демо.
6. Изменение подтверждённой задачи: предпросмотр → явное подтверждение; отмена сохраняет старое состояние. Учитывать роль из capabilities, но не считать скрытую кнопку защитой. После потери сессии/прав объяснить ситуацию и сохранить несекретный несохранённый ввод в памяти текущей сессии; не переносить закрытый ответ между пользователями.
7. Состояния loading/empty/error/retry, защита от двойного нажатия, предупреждение о несохранённом, адаптивность 360/768/1440 px, клавиатура, label, фокус в диалоге и возврат фокуса, Escape закрывает предпросмотр. Долгая генерация не блокирует всё приложение.

## Параллельная работа и приёмка

Сразу делай интерфейс на изолированных фикстурах `tests/ui_track3/` строго по CONTRACT. Заглушки запрещено молча использовать в основном интерфейсе и выдавать за работающую модель. После поставки серверных PR проверь настоящий HTTP-путь.

Проверить: роль чтения, вход/выход без остатка чужих данных, календарь cancel/confirm/409, редактирование протокола, выбранные задачи без дублей, QA с источником и без ответа, обзор, feedback, ошибки 401/403/404/503, мобильный экран и клавиатура. Минимум `node --check static/meetings.js`, содержательные UI-тесты важных действий и ручной/автоматизированный браузерный smoke. Не писать тесты, которые лишь сравнивают строки исходника.

Не трогать речь ради полировки: уже есть рабочий all-speakers режим с согласием, его надо сохранить. Не обещать автоматическое определение говорящих. OCR, полноценный чат с памятью и новый дизайн всего кабинета — вне задания.

Handoff: SHA, экраны/сценарии, фактические браузерные проверки и размеры, API-проблемы конкретными примерами, ограничения. Исправляй интеграционные дефекты только в своей зоне. Перед PR проверить staged-пути и отсутствие чужих изменений.
