# Распознавание во время записи — 13 октября 2026

## Реализованный режим

Обычный кабинет (`static/app.js`) в локальном режиме и MTS-оболочка
(`static/mts-shell/local-voice.mjs`) используют общий `static/incremental-stt.js`.
AudioWorklet (`static/pcm-capture-worklet.js`) захватывает моно PCM и приводит его
к 16000 Hz. Каждый запрос содержит самостоятельный PCM16 WAV, не кусок WebM
без заголовка. Системный микрофон не меняется; используется уже разрешённый браузерный поток.

При тихом участке примерно 400 мс завершённый фрагмент начинает распознаваться,
пока общая запись ещё идёт. Следующее разделение не чаще одного раза в 3 секунды.
Жёсткого разрезания непрерывной речи через N секунд нет: без паузы сохраняется
весь оставшийся фрагмент. При перегрузке ожидающее аудио объединяется; в этой
реплике одновременно идёт не больше одного запроса распознавания.
RMS браузера только планирует запросы. Silero VAD на сервере определяет наличие речи.
При завершении всегда отправляется остаток аудио, даже если его уровень был ниже RMS-порога.
Последний пакет PCM сбрасывается с подтверждением от Worklet перед сборкой текста.

В интерфейсе «Уже распознано» — предварительный результат, не реплика диалога.
Части идут в исходном порядке, повторённые слова не удаляются эвристикой.
`POST /api/transcribe/assemble` применяет нормализацию ко всей реплике, используя
последний вопрос ассистента из сохранённого разговора. Так группы цифр телефона
не нормализуются независимо и не теряют границы. Этот endpoint не вызывает LLM,
не записывает сообщения и не выполняет инструменты.
Только окончательный текст отправляется в существующий `/api/chat` один раз.
Подтверждение действий, происхождение данных и правила runtime не изменялись.

Автоматическое завершение по тишине осталось прежним — около 1050 мс.
Параллельно MediaRecorder сохраняет полную запись в памяти до окончания реплики.
Если Worklet/фрагмент/сборка дали ошибку, UI сообщает о переходе к распознаванию
всей записи тем же локальным Whisper. Облачного fallback нет.
Stop отменяет запрос и очередь, поздние результаты не попадают в диалог;
уже выполняющийся CPU-инференс внутри сервера HTTP-отмена мгновенно не прерывает.

## Проверка

- Python: сборка телефона через границы, пустые части, реальные повторы слов,
  отсутствие обращений к LLM и записей, ограничения длины, закрытый/неизвестный разговор.
- Node: точные WAV-заголовки и число семплов; распознавание до finish; сохранение
  тихого хвоста; отсутствие произвольного разрезания речи; очередь и порядок;
  Stop; ошибки; ресемплинг 16/44.1/48 kHz; финальная реплика вместо частичных сообщений;
  восстановление по полной записи при ошибке фрагмента.
- Браузер: `/static/tests/streaming-stt.html` запускает синтетическую речь в реальном
  времени через настоящий AudioWorklet → HTTP → Silero/Whisper → сборку → Qwen.
  Тест не запрашивает доступ к микрофону и создаёт отдельно помеченные тестовые разговоры.
  Полная и фрагментная версии используют одинаковую волну и прогретую модель.
  Метрики «после остановки» относятся к распознаванию, не ко всему времени до голосового ответа.

## Ограничения и следующий шаг

Первый браузерный замер: короткая запись 2,53 с — после остановки 1820 мс по частям
против 2066 мс целиком; длинная 9,48 с — 2074 против 2884 мс. На длинной записи
первая расшифровка появилась до её завершения. Слова в обеих версиях совпали,
кроме пунктуации. Это два синтетических примера, не средняя задержка человеческих разговоров.
Отдельный ответ Qwen в этих проверках занял 2,7–2,8 с и не входит в время STT.

Повторный замер: короткая — 2003 против 2006 мс (фактически без выигрыша);
длинная — 1956 против 2786 мс (экономия около 830 мс).
На короткой реплике предварительный результат в обоих запусках не успел появиться
до окончания записи. Не обещаем мгновенный ответ или устойчивое ускорение коротких фраз.
Полные результаты обоих запусков: `proof/incremental-stt/browser-results.json`;
снимок второго запуска: `proof/incremental-stt/browser-results.png`.

Полный Python-набор: 385 passed, 12 skipped. Node-набор распознавания,
воспроизведения и MTS-транспорта: 20 passed.

RTX 5060 Laptop GPU видна CTranslate2, однако отдельная попытка запуска Whisper
на GPU завершилась ошибкой `Library cublas64_12.dll is not found or cannot be loaded`.
В текущем окружении GPU-запуск не работает. Рабочий CPU-режим не менялся,
CUDA-библиотеки не устанавливались; требуются отдельная подготовка окружения и замер.

Это первый режим с разделением по паузам, не полноценный токенный streaming ASR.
Непрерывная речь без пауз не будет постепенно расшифровываться этим способом.
Модель Whisper Small CPU INT8 не заменена; отдельных CUDA/новых весов не установлено.
Распознавание коротких частей может отличаться от цельной записи. Для имён,
диктовки цифр, негромкой речи, шума и человеческих пауз нужна отдельная проверка.

Если задержка CPU остаётся большой, следующий этап — оценить GPU-запуск
текущего Whisper и специализированный streaming backend с перекрытием и
подтверждением стабильных слов. Не объявлять это внедрённым в текущей итерации.
Ускорение STT не убирает задержку LLM, озвучки и детектора окончания фразы.

Источники:
[Faster-Whisper: API и требования GPU](https://github.com/SYSTRAN/faster-whisper),
[WhisperLiveKit: специализированный streaming ASR](https://github.com/QuentinFuxa/WhisperLiveKit).
