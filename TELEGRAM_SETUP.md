# Telegram, регистрация и доступ владельца

## Что уже работает локально

Бот запускается вместе с FastAPI, без отдельной подписки и без публичного webhook.
Нужны интернет, токен BotFather и работающий процесс Callwise. Регистрация в личном чате:
`/start` или `/register` → имя → бизнес → «Да» на конкретное согласие.
Без «Да» регистрационный профиль не создаётся. Незавершённый черновик действует 30 минут.
`/profile` показывает только профиль отправителя; `/cancel` удаляет незавершённый черновик.
Удаление профиля: `/delete_profile` → отдельное предупреждение → `/confirm_delete` в течение 5 минут.
Удалённый профиль не восстанавливается; существующие обращения и привязки уведомлений не удаляются.

Профиль содержит Telegram ID, имя, название бизнеса и версию согласия.
Регистрация не авторизует пользователя в локальном кабинете, не создаёт агента автоматически
и не открывает доступ к чужим агентам/разговорам. Мультиарендный кабинет ещё не реализован.

## .env и запуск

Файл: `autofix-receptionist/.env`. Действующие ключи Groq/SMTP не заменялись.

```env
TELEGRAM_BOT_TOKEN=токен_из_BotFather
TELEGRAM_ENABLED=true
TELEGRAM_MINIAPP_URL=
CALLWISE_OWNER_PASSWORD=
```

Токен нельзя публиковать, присылать в чат или включать в архив.
После изменения `.env` перезапустите сервер. В PowerShell из каталога проекта:

```powershell
./start.ps1
```

Скрипт использует окружение `.venv` и устанавливает requirements.txt.
Запускайте один рабочий процесс. После аварийной остановки восстановление аренды poller
может занять до минуты. При конфликте с другим приложением или существующем webhook
бот покажет ошибку; Callwise не удаляет чужой webhook автоматически.

## Доставка обращений владельцу

1. Создайте помощника в «Быстром старте», проверьте и сохраните настройки.
2. Откройте «Telegram» и выберите этого помощника.
3. Создайте одноразовую ссылку, откройте в своём Telegram и нажмите Start. Ссылка действует 10 минут;
   не передавайте её другим. Нажатие Start пока только предлагает получателя.
4. Вернитесь в Callwise, нажмите «Проверить получателя», проверьте имя/Telegram ID и подтвердите.
5. Проведите новый тестовый диалог и подтвердите обращение. До согласия очередь пуста.
6. В «Обращениях» обновите историю и проверьте статус Telegram.

Привязка действует на конкретного агента. Новая привязка не отправляет старые обращения
и отменяет ещё не начатые отправки предыдущему получателю. Отключение не удаляет уже отправленные сообщения;
отправка, уже начатая перед отключением, может завершиться.
Смена токена требует повторной привязки: старые получатели не используются новым токеном.

Обращение и запись в outbox сохраняются в одной SQLite-транзакции. Сетевой вызов не задерживает
голосовой ответ. Статусы: pending, sending, retry, sent, failed, unknown, cancelled.
sent означает успешный ответ Telegram с message_id, не прочтение человеком.
429 учитывает retry_after, максимум пять попыток. При таймауте/разрыве связи/сбойном серверном ответе
результат неизвестен: автоматического повтора нет, иначе можно создать дубль.
После сбоя процесса sending также становится unknown. Exactly-once доставку Bot API не гарантируем.
Ошибки не удаляют подтверждённое обращение. SMTP прежнего демо не используется для новых агентов.

## Telegram Mini App

Код готов: GET `/miniapp`, POST `/api/miniapp/profile`, POST `/api/miniapp/register`.
Локальный предпросмотр: http://127.0.0.1:8000/miniapp.
В обычном браузере кнопка сохранения заблокирована: нет проверенной Telegram-сессии.

Для запуска внутри Telegram нужен **публичный HTTPS-адрес**, например `https://ваш-домен/miniapp`.
Его нужно установить в TELEGRAM_MINIAPP_URL, а origin сервера — в PUBLIC_ORIGIN, затем перезапустить.
Тогда `/register` покажет кнопку «Открыть регистрацию» вместо текстового мастера.
Публичного размещения/туннеля в этой итерации нет. Указание HTTPS-URL само по себе не подтверждает размещение.

Сервер проверяет HMAC-SHA256 initData по официальному протоколу Telegram, auth_date до 10 минут,
повторяющиеся ключи и корректный user ID. initDataUnsafe и присланному браузером telegram_id
не доверяем. Токен остаётся на сервере. Старую Mini App нужно открыть заново по истечении сессии.
Подписанная регистрация не выдаёт cookie владельца и не предоставляет доступ к основным API.

Перед публичным запуском: защищённый HTTPS reverse proxy, отдельный секрет владельца,
ограничение запросов на уровне прокси, резервные копии, согласованная политика хранения/удаления,
наблюдаемость и проверка нескольких реальных Telegram-клиентов. Не открывайте порт 8000 в интернет напрямую.

## Вход владельца

CALLWISE_OWNER_PASSWORD длиной от 12 символов включает общий вход одного владельца.
Есть подписанная cookie на 8 часов, HttpOnly/SameSite=Strict, Secure на HTTPS,
ограничение неудачных попыток и запрет cross-site API/чужих Host.
Пустой пароль оставляет локальное демо; удалённые API кабинета блокируются.
При коротком непустом пароле вход блокируется. Пароль задаёт пользователь локально.
Это не RBAC/изоляция арендаторов и не production-подсистема аккаунтов.
Для отзыва всех текущих сессий смените пароль и перезапустите сервер.

## Проверки и источники

13 октября 2026: полный прогон **316 passed, 12 skipped** (70,11 секунды).
25 новых проверок Telegram/регистрации/доступа пройдены. Пропущенные проверки не считаются пройденными.
Синтаксис новых JS-файлов проверен. В браузере проверены раздел Telegram, состояние работающего бота
и запрет сохранения Mini App без Telegram-сессии; ошибок JavaScript в этой проверке нет.
Снимок формы: docs/telegram-miniapp.png. Публичное размещение не выполнялось.

`./.venv/Scripts/python.exe -m pytest -q` — обычный тестовый прогон.
Тесты изолируют реальный Telegram-токен: имитируются получение updates и ответы Bot API,
проверяются подписи/сроки, согласие, доступ к собственному профилю, привязка, outbox, ошибки и вход.
Живой запуск проверяет getMe/getWebhookInfo и polling. Регистрацию реального пользователя и
доставку в его чат нужно подтвердить вручную; Mini App внутри Telegram без HTTPS ещё не проверен.
