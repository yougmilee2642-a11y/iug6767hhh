# Callwise: локальный тестовый режим

Рабочая копия на компьютере Лёши: `D:/Projects/Callwise-local`.
Исходная облачная копия и её секреты не изменены. Этот файл описывает именно локальный режим,
а не все старые возможности из README и отчётов предыдущих итераций.

## Выбранная конфигурация

- Текстовый диалог: Ollama, `qwen2.5:3b`, Q4_K_M, контекст 8192, до 384 выходных токенов.
- Распознавание: T-one ONNX CPU для предварительного текста и GigaAM v3 RNNT, CUDA FP16 encoder на RTX 5060 Laptop GPU, для полной реплики.
- Фильтр говорящего: pyannote segmentation + WeSpeaker ONNX CPU; образец из первой чистой реплики, без сохранения аудио на диск.
- Проверка наличия речи: Silero VAD ONNX, CPU.
- Озвучка: Silero `v5_ru`, голос `xenia`, CUDA, WAV 48 kHz; словарь произношения перед синтезом.
- Модели и загрузки находятся в `models/` и `downloads/`, не входят в исходники.

Подробности новой связки и её ограничения: [docs/LOCAL_ASR.md](docs/LOCAL_ASR.md).
Открыть отчёт проверки: http://127.0.0.1:8000/static/qa/dual-asr-verification.html

Qwen2.5 скопирована из уже установленного локального кеша; контрольные суммы всех её
блоков проверены. Загрузка Qwen3 остановлена по запросу. Части сохранены в
`downloads/qwen-parts`; их можно возобновить вручную. `finish-local-install.ps1`
предназначен только для будущего перехода на Qwen3: он скачивает её и проверяет отдельно.
Не запускайте его для обычного тестирования Qwen2.5.

## Запуск на этом компьютере

Запустить `start-local.ps1` из каталога проекта и открыть `http://127.0.0.1:8000/#quick`.
Настройки — в `.env`. При изменении модели нужно перезапустить приложение.
Если открыто несколько окон с сервером, сначала остановить старый экземпляр, иначе порт занят.
Модель загружается в GPU при первом запросе; первый ответ может быть медленнее последующих.

Для нового компьютера: установить Python 3.11 и Ollama; создать собственную `.venv`,
установить `requirements-local-gpu.txt` для NVIDIA CUDA (либо CPU PyTorch и `requirements-local.txt` без GPU), скопировать `.env.local.example` в `.env`
без перезаписи существующих секретов. Установить `qwen2.5:3b` через Ollama и однократно
запустить `scripts/install-local-models.py` для речевых весов. Загрузка требует интернета;
обычный запуск не скачивает отсутствующие веса автоматически.
Без CUDA явно задать `LOCAL_STT_DEVICE=cpu`, `LOCAL_TTS_DEVICE=cpu`, `LOCAL_STT_COMPUTE_TYPE=int8`; GPU-пример `.env` сам по себе не устанавливает runtime.
Не копировать `.venv` между компьютерами. У этого компьютера среда использует уже установленный
CPU PyTorch через system-site-packages ранее; 14 октября CUDA PyTorch установлен отдельно внутри `.venv`, системная CPU-сборка не удалена. Для второго компьютера создать независимую среду. GPU-установка, фактические устройства и замеры: [GPU_VOICE.md](docs/GPU_VOICE.md).

## Что проверено

`scripts/smoke-local.py` использует настоящие модели и временную SQLite-базу. Он блокирует
внешние Python-соединения, синтезирует русскую фразу, распознаёт её и затем проводит
текстовый диалог с Qwen2.5 до подтверждения и сохранения ровно одного обращения.
Это не проверка человеческого микрофона, шума или телефонного звонка.

В успешном тесте на этом ноутбуке: распознавание тестовой фразы 2,61 с;
ответы модели 1,13–1,53 с; первое после загрузки озвучивание 1,73 с.
Это отдельные этапы, не обещание такой задержки полного голосового разговора.
Ollama сообщает `100% GPU`, около 2,4 GB с загруженным контекстом 8192.

Небольшая модель сначала повторяла вопросы. Runtime теперь передаёт ей явный текущий шаг
для помощников «Быстрого старта». Это уточнение промпта, не обход проверок: происхождение
полей, подтверждение и запись по-прежнему контролирует сервер. Один успешный сценарий
не доказывает качество модели на всех агентах, FAQ, конструкторе или календарных сценариях.

## Ограничения

### Распознавание по частям во время речи (13 октября 2026)

В обоих локальных веб-интерфейсах распознавание начинается во время коротких пауз,
до окончания общей записи. Части собираются в одну финальную реплику и только
затем передаются в AI. При ошибке фрагмента распознаётся сохранённая полная запись
тем же локальным Whisper; предварительный текст в историю не записывается.
Непрерывная речь без пауз пока остаётся одним фрагментом. Порог завершения по тишине
не сокращался. Подробности и тестовая страница: [INCREMENTAL_STT.md](docs/INCREMENTAL_STT.md).

### Произношение русской речи (13 октября 2026)

Перед локальной озвучкой сокращения «МТС» и «СМС» раскрываются в названия букв,
телефон с `+` и короткий USSD-код — в последовательность цифр. Небольшой явный словарь
задаёт ударения; Markdown и SSML-разметка не передаются в модель как команды.
Исходный ответ, история и данные заявки не меняются. Это не исправление всей русской
грамматики и не дообучение модели. Автоматические ударения и «ё» в установленной модели
уже были включены; специфические правила добавлены поверх них.

`LOCAL_TTS_SAMPLE_RATE` задаёт частоту WAV (по умолчанию 48000).
`LOCAL_TTS_SPEAKER` выбирает установленный голос: `xenia`, `baya`, `kseniya`, `aidar`, `eugene`.
Изменения `.env` требуют перезапуска. Неправильные настройки возвращают ошибку, без
автоматического переключения на облачную озвучку.
Образцы и границы проверки: [TTS_PRONUNCIATION.md](docs/TTS_PRONUNCIATION.md).

### Ускорение голосового ответа (13 октября 2026)

В запросе к Qwen стабильные правила и данные идут перед текущим временем, чтобы повторно
использовать обработанный префикс. Время остаётся актуальным на каждом ходе; история не обрезается.
LLM и озвучка прогреваются при запуске без клиентских данных и без инструментов.
Это переносит часть задержки первого ответа на запуск сервера.

Whisper пропускает только тишину по краям записи с запасом 200 мс, сохраняя паузы внутри.
Неиспользуемые метки времени не генерируются. Модель распознавания не заменена на меньшую.
Длинный уже проверенный ответ озвучивается по предложениям: следующая часть готовится во время
воспроизведения первой. Остановка разговора отменяет оставшуюся озвучку; ошибки не скрываются.

Во время записи есть кнопка «Отправить фразу сейчас», чтобы не ждать автоматической паузы.
Автоматический порог тишины оставлен прежним. Ограничение одной локальной реплики - 120 секунд.
Проверки происхождения данных, подтверждения действий и локальная изоляция сохранены.
Распознавание на CPU всё ещё занимает около 2,5 с на коротких тестовых репликах;
общая задержка зависит от длины речи, ответа и нагрузки компьютера.

В `CALLWISE_LOCAL_ONLY=true` отключены Groq, Edge TTS, Telegram, email и облачная Evaluation.

Локальная проверка сценариев теперь доступна из карточки помощника. Она использует
ту же установленную Ollama и временную БД для каждого разговора. Приём обращения
проверяется по реальным событиям инструмента и явному подтверждению. Оценка текста
самой моделью предварительная; отсутствие независимой проверки не выдаётся за READY.
Пока идут сценарии, ручной разговор может отвечать медленнее. При недоступной Ollama
запуск блокируется с объяснением; внешнего AI-fallback нет.
Это сознательная изоляция; Telegram-бот не работает параллельно в этой копии.
Телефония не подключена. Запись в браузере заканчивается по текущему детектору тишины;
Silero анализирует полученный фрагмент на сервере, не заменяет его потоковым full-duplex VAD.

Лицензия Silero TTS включает некоммерческое ограничение: для коммерческого пилота нужна
проверка прав и, возможно, другая озвучка или разрешение правообладателя.
